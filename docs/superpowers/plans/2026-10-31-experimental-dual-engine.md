# Experimental Coupled Dual Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Independent review is required before numerical admission and before any integration proposal; this plan does not select an implementation subagent workflow.

**Goal:** Build an opt-in Float64 dual engine that maintains owned invariants and coordinates proposal, publication and recovery, then judge its total cost to a verified solution against current master.

**Architecture:** A separate experimental module owns one phase workspace, indexed scratch, violation membership, pending numeric writes and an undo journal. A nonrecursive controller drives checked proposals and a private commit protocol. Existing initialization, factor interfaces, cleanup and original-model certification remain available at explicit counted boundaries; production defaults remain unchanged.

**Tech Stack:** Existing Julia project, Float64, SparseArrays CSC, production PFI/native backend, fixed Devex, ordinary Test; no new dependency, module clone or method overwrite.

## Review Focus

1. Preexisting infeasible prices outside tableau support must remain in maintained membership and prevent a false normal/terminal decision; Task1/3 tests.
2. A failed factor update may partially mutate a backend, and failure after numeric writes must restore private values without claiming factor rollback; Task4 tests.
3. Cancellation, tiny/subnormal coefficients, signed zero and dense output must preserve complete residual/scale coverage; Task2 tests.
4. Unknown aliases, stale proposal generations, generation wrap and mutable callbacks must invalidate evidence or select legacy before ownership; Task1/4/5 tests.
5. An apparent fast result dominated by immediate legacy fallback or final certificate failure is not a successful engine benchmark; Task5/6 activation and result tests.

## File structure and interfaces shared by tasks

Create under `experimental/dual_engine/`: `ExperimentalDualEngine.jl` (module and includes), `types.jl`, `state.jl`, `invariants.jl`, `support.jl`, `kernels.jl`, `ratio.jl`, `proposal.jl`, `commit.jl`, `recovery.jl`, `driver.jl`, `test/runtests.jl`, `test/fixtures.jl` and focused test files listed below. Include the installed/current project `JSimplex` once as `J`; do not include a second copy of all production sources. The experimental module is not included by default from `src/JSimplex.jl`.

Task5 may modify only the necessary internal handoff signatures/call sites in `src/solver.jl` and `src/dual_simplex.jl`; no public `solve` signature/default change. Task6 adds `diagnostics/dual-step-experiment/measurement/` with ordinary runner/admission/report. Preserve production tests intact.

Names below live in `ExperimentalDualEngine` (E). Store types parametrically where concrete workspace/factor/clock types are needed; do not type hot fields as Any or Function.

- `EnginePolicy`: immutable parameters defined in Task1; `EngineCounters`: fixed scalar fields, including accepted normal pivots, proposals, rejections, each FTRAN/BTRAN attempt including throws, BFRT FTRAN, refactors, corrections, scanned entries, touched entries, support captures, row-index builds, dense routes and legacy boundaries.
- `EngineState{W,C}`: owned `ws::W`, `clock::C`, policy, counters, generation, invariant state (including an N-entry variable-to-basic-row map), scratch, proposal and journal. The factor is owned through ws, not independently aliased into another live workspace.
- `StepOutcome`: typed reason enum plus entering/leaving IDs and no borrowed mutable result graph. Outcomes include Ready, Committed, PrimalFeasible, RowUnreliable, DirectionUnreliable, RatioUncertain, FactorInvalid, NumericWriteFailed, Stopped and Exhausted.
- `StepProposal`: owned preallocated scratch with generation-bound validity, scalar steps, flip IDs and parallel planned value arrays. `UndoJournal`: matching old-value arrays, first-write stamps, field masks and old scalar/basis state. Their capacity is N, their used length is t, and their references never escape the engine.
- `PhaseResult`: terminal status/reason, counters and an owned/exportable committed workspace at a synchronized boundary; it is not an original-model certificate.

### Task 4: Journaled commit and flat recovery controller

**Files:** Create `commit.jl`, `recovery.jl`, `test/{commit_tests,recovery_tests}.jl`; extend counters and work/memory ledger.

**Interfaces:** `commit_step!(e)::StepOutcome`; `restore_journal!(e)::Nothing`; `recover!(e,cause)::StepOutcome`; `run_phase!(e)::PhaseResult`. RecoveryStage enum covers Normal, CorrectRow, CorrectDirection, RebuildBasis, Reprice, ResetDevex, LegacyBoundary and Terminate; a single loop owns transitions and budgets.

- [ ] Write sentinel-injection tests before implementation: partial factor-update mutation then exception; failure after first/middle/last numeric write; capacity refusal before writes; stale proposal; deadline before commit and during factor call; generation wrap; event/logger exceptions after commit. Require original owner/basis/state on rejection, no completion event for uncommitted work, and invalid factor never used in another solve. A post-commit observer exception propagates and does not pretend the already committed state rolled back.
- [ ] Run admitted RED. Gather old values for each proposal union ID once using first-write stamps. Reserve all capacity before mutation. Apply factor update, then precomputed numeric writes with fused finite/classification checks, then basis/scalars/generation, then one immutable completion event. No external callback in the write interval and no live engine arrays in that event. Failed numeric publication restores every journal field and invalidates summaries/factor evidence before any next decision.
- [ ] Implement recovery as dependency-directed transitions: up to3 correction solves of the failed equation and fresh residual checks; row correction discards pricing/ratio/FTRAN, direction correction discards dependent pivot/write plans. Failed same-precision correction requests rebuild/reprice, at most2 rounds. Each refreshed generation clears obsolete rejection sets, but does not reset the current stuck-decision rebuild/correction budgets; only a committed pivot ends that recovery episode. Refactor itself reconstructs the current committed basis and owned values, rebuilds invariants/Devex once, then resumes. Honor configured factor ceiling even during apparently productive zero-step sequences.
- [ ] Use the policy's8 entering/8 leaving rejection limits per generation, monotone total counters and the original deadline. Exhausted rebuild budget leads to one validated legacy boundary or honest numerical termination; do not reset budgets by recursion or repeatedly fall back and re-enter. A damaged factor can be discarded on timeout without forcing a late expensive repair; return no unverified solution payload. Readiness to export requires restored journal, committed basis/values, valid summaries and a reconstructed/valid factor.
- [ ] Test real same-precision numerical corrections separately from injection accounting, old factor invalidation/rebuild, recurrence termination, phase offsets, cost restoration and all repair counters. Prove selective invariant updates against full cold scans after every accepted/rejected transition. Run GREEN, independent state/exception/work review then commit.
