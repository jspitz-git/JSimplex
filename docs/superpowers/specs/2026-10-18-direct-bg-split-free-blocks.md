## Chosen scope and alternatives

Keep the existing column-contiguous representation, maximum block B=32, append slab A=256, compact Int32 row handles,32capacity bins, exact initial bulk import, row-gap rule and descriptor/directory growth. Change only how a FREE extent is sized for an allocation request. Do not add a coefficient mirror, new row storage, global compaction, cache, solve fast path or numerical safeguard change.

Smaller slabs alone leave active32-position slack. Global packing adds O(C+R+K) work to updates and changes handle lifetime. Instead split one free extent locally; accept explicit extra descriptors and possible later fragmentation. Free-extent coalescing/reclamation is excluded from this first design and must not be silently added to rescue costs.

## Exact allocation policy and interfaces

Future standalone sources use `BGSplitUpper`, prefix `_sbu_`; adapter `SplitBGFactor{F}`, prefix `_sbg_`. They are distinct types/methods in a new diagnostic stage, never overwrites or new dispatch on old types.

`_sbu_target(required::Int)::Int`: accept1<=required<=32, otherwise throw ArgumentError before mutation. Return smallest of1,2,4,8,16,32 >=required. For an empty column required=1; for a nonfull existing block required=count+1; full32 numerical split still requests32. The class is chosen before free-list search: a free capacity3 does NOT satisfy a request3 with target4. Exact imported tail extents and arbitrary split remainders remain valid and reusable when they meet a later target. This deliberate geometric policy may leave small free extents stranded; account for them.

`_sbu_reserve_block!(U::BGSplitUpper,required::Int,allocate,limit::Integer)::Int` returns the ID of a free block with capacity EXACTLY target and count=column=0, still on its bin list. The caller takes it at the existing commit point. No reservation object is retained; private synchronous use permits only one outstanding reservation and no intervening allocation request. Existing insertion must obey this contract; tests exercise reserve then take.

1. Compute target; inspect bins target:32 in ascending capacity, taking the current head of the first nonempty bin. At most32bin reads. Do not inspect coefficients or scan other descriptors/slabs/rows.
2. If no fitting block exists, use the existing append transaction: private zeroed three256element buffers and needed descriptor/directory reserves, then publish eight free32extents. Select the same bin32 head the current allocator would select.
3. If donor capacity equals target, return its ID unchanged. If larger, reserve exactly ONE additional descriptor ID `used+1`, growing the seven descriptor arrays with the existing rule if necessary. Before unlinking donor, check ID/handle limit, `start+target`, remainder end and all local bounds; complete all fallible allocation/validation.
4. Split the donor physically into the LOW-address target prefix and the remaining suffix. Donor keeps its ID/slab/start, receives target capacity and remains free. New ID gets same slab,start+target,capacity=old_capacity-target,count=column=0. Publish used+1 and reinsert both through their own capacity bins. All seven descriptor fields are initialized; free prev/next links must not be confused with active column links. No coefficient buffer copy or clear occurs: a free donor's entire physical extent already contains cleared cells under the inherited invariant.
5. Return donor ID. Splitting a free extent changes no active handle, row back-reference, coefficient, live count, column order or history. Larger remainder need not be a power of two. Physical extents partition every allocated slab with no overlap or orphan positions.

No new BGBlockUpper-style fields or per-request heap objects are required. Use existing `used` as initialized descriptor high-water. IDs1:used own positive-capacity extents, active or free; spare descriptors used+1:K own no extent. Active descriptor identities stay stable. Every split adds one positive extent; at any state used<=C (C=sum slab lengths), but C and K are high-water capacity, not bounded by live count. No descriptor recycling/coalescing scheme is introduced.

When an occupied short block must grow, the inherited relocation swaps slab/start/capacity with the sized free donor, copies the old live prefix, clears the old extent and returns it to its bin. Active ID and its row handles stay unchanged. The destination's capacity is target, not32. Since an imported exact tail may have non-power capacity, its first growth may be less than doubling; subsequent growth of that active block follows power-of-two classes. Deletion/merge can change this premise, so no lifetime logarithmic bound applies across arbitrary mutation sequences.

## Correctness, ownership and failure

Preserve numerical multiplication/subtraction/division order, exact zero and signed-zero handling, finite checks, pivot/zero_tolerance, exception behavior, prepared entering+DSE spike provenance, policy/backend/export/normalization, row/column maps, history/cache invalidation and supported precision boundary. Float64/Int private direct BG only, native threshold_one and Markowitz default. No FT/SS/HH/public/indexed/general-precision extension.

All fallible work precedes free-bin publication. Descriptor growth can publish larger unused metadata; slab append can publish wholly free reserve before a later split-descriptor failure. Such reserve changes are permitted on allocation failure. Logical live values, row/column order, encoded handles, unique ownership and complete partition must remain valid. In inherited insertion, row reserve occurs before block reserve: a completed row or descriptor reserve may replace backing arrays and repair reciprocal physical row positions before a later allocation fails. Their original backing identities and physical positions need not survive; their consistency must survive. The free-split helper itself changes no active extent or row handle. These reservation guarantees apply before numerical mutation, separately from earlier committed numerical edits in a failed update. Failed individual reservation must not detach or lose donor/remainder or expose uninitialized descriptors. Test each seven-array allocation failure and append/directory boundary. Update remains nontransactional after earlier numerical edits; do not use a failed factor until refactor. Full refactor publication and copy isolation retain the old contract.

Structural checks must include sum capacities=C across descriptors1:used; active+free partition; capacity bins exact and acyclic; disjoint slab extents covering all positions; no spare descriptor referenced; active handles offset<=count<=capacity<=32; reciprocal row positions; free cells cleared. No such whole-structure check belongs in production solve/update loops. A future implementation must check local preconditions once and preserve index/overflow rejection before mutation; no blanket bounds-check removal.

## Memory ledger

Representation is unchanged. With C coefficient capacity,R row capacity,K descriptor ARRAY capacity,S slabs,D directory capacity,n dimension, core payload remains

`P=16C+4R+28K+32n+656` bytes,

plus outer pointer payload `8n+24D`, all Vector/Memory/struct headers/backing reserves, lower/backend state, updates/recycled history/work/prepared caches. S<=D. Array graphs overlap: never sum them as a whole-factor graph. Free/live slack, initial exact tails, split remainders and spare K/D must all be counted. Native live/peak/free behavior is not inferred from these payloads or Julia summarysize.

A free split alone leaves C,R,S,D unchanged, adds one initialized descriptor, and adds no coefficient allocation. If spare K exists, it adds no buffer allocation. If K must grow, all seven new arrays are allocated and old prefixes copied: new payload28*Knew, copied payload28*Kold, temporary old+new descriptor payload28*(Kold+Knew), plus headers. The arithmetic28bytes per initialized descriptor is NOT the cost of a geometric growth event. Original rule Knew=max(required,Kold+max(Kold div2,8)) remains, including checked32*Knew. Append adds4096entry payload bytes, three buffers,8descriptors and possible K/D growth; a following split may need descriptor9 and cause another growth if capacity is insufficient. Report both, do not assume they fuse. Directory coexistence is24*(Dold+Dnew) plus array headers; rows retain existing4*(Rold+Rnew) local coexistence and capped+8growth.

No global memory bound proportional to current live entries is claimed: arbitrary noncoalesced remainders/high-water slabs can force append despite ample total free capacity. Copy must preserve all partition metadata and retained buffers; refactor owns old+new graphs plus backend/export temporaries until publication. Final and every intermediate graph gate remain mandatory.

## Work ledger and regression risks

Setup/refactor initial bulk import stays O(n+m), exact C=R=m/K0 counts unchanged; no eager rounding or extra scan. FTRAN/BTRAN code changes only type/helper names: zero new per-RHS scans, solves, caches or conversion; their prior overhead may remain. Each free request costs target selection over at most6classes + at most32bins + O(1) split metadata/link writes when capacity exists. No recursive splitting and at most one remainder descriptor per request. K/D reserve copies and buffer initialization are separately counted amortized/high-water costs, never hidden as O(1).

Each occupied-block growth copies its old live prefix (<=31 tuples), clears its old capacity (<=31 cells), swaps descriptors and preserves handles. For uninterrupted monotone fill starting empty until capacity32, power-class relocations copy at most1+2+4+8+16=31old tuples; initial exact tails fit the same bound from their starting capacity. This bound excludes later deletion/merge/refill, which can repeat migration. Full33entry numerical split, merge, row gaps/rotations/back-reference repairs, spike/replacement scans and history work remain as before. Retain the capped row reserve worst case Theta(f*d+f^2) and original O(n+visited entries+blocks+history) solve bound.

The existing allocator often migrated directly to32 once. Progressive smaller extents may therefore increase relocation/clearing and descriptor traffic, especially for dense columns. Dense96's prior update advantage and narrow1.094761graph ratio are explicit regression risks. Extra fine-grained bins/descriptors are not presumed free. Do not bundle diagonal-lookup hoisting, new solve fast paths, bulk replacement, row growth changes, smaller slabs, coalescing or backend changes into this design.
