## Fixed representation

First design constants: maximum block length B=32; additional slab size A=256 entries; all stored IDs/offsets/handles are Int32 with0sentinel. Computational loops use Int after checked decoding. No size/backend-specific tuning after outcomes. The private factory rejects unsupported dimension/index capacity; it does not silently narrow, widen or dispatch to the old candidate. n, slab offsets, row capacity+1, descriptor capacity and encoded handles must fit; checked K*32<=typemax(Int32). Validate n before backend work and exported sizes before publishing a new factor. Future growth overflow throws before the current storage primitive mutates. A partially completed BG update is still not transactional; refactor is required after its failure.

`BGBlockUpper` owns:
- Three parallel slab directories: Vector{Vector{Float64}} values, Vector{Vector{Int32}} row_id and row_back. An occupied entry contains a stable physical row ID and the PHYSICAL offset in that row's gap-buffer vector. Values are stored once. No per-entry column ID or linked-list pointers.
- Seven equal-capacity Int32 descriptor arrays: slab,start,capacity,count,column,prev,next. Active descriptors own disjoint contiguous extents of at most32entries; live entries occupy the prefix1:count. Prev/next link BLOCKS of one stable column in ascending logical-row order. Empty free blocks have count=column=0; prev/next serve capacity-bin links. There are32free-bin heads. Descriptor IDs do not move when arrays grow.
- Four Int32 inverse maps row_order/row_position,column_order/column_position and two column head/tail vectors. Stable column IDs equal ORIGINAL basis IDs q[j], not logical CSC positions.
- One row incidence Vector{Int32} per physical row, plus gap_first/gap_length Int32 vectors. Non-gap handles are sorted by stable column ID; gap cells are0. Each live coefficient occurs once. row_back points to the physical vector offset, including the gap shift. Per-row gap capacity may exceed degree; it is included in R below.
- Three owned scratch arrays of length33: Float64 value and Int32 row_id,row_back. They stage a block edit without allocating per coefficient. Scalar n, live count, descriptor/slab counts and counters of initialized capacity; no diagnostic ledgers in the candidate.

Handle h=(block_id-1)*32+offset, with1<=offset<=count<=32. Decode using div/rem on h-1. It identifies a descriptor and offset, not a stable coefficient identity. Handles must not escape the current primitive/update into history, a prepared spike or callers. Block relocation changes descriptor.slab/start but preserves handles; moving entries within a block updates exactly their row-buffer handles through row_back. A row gap movement updates row_back through handles. No O(nnzU) reverse search is allowed.

Initial construction uses one exact-sized slab of m=stored CSC entries (no minimum256reservation); split each nonempty logical column into consecutive blocks of at most32 with capacity=count, including exact-sized tails. Empty matrix uses no coefficient slab. Imported explicit zeros including signed zero are stored as the reference does. K0=sum(ceil(degree_col/32)); C0=R0=m. Build q inverse/maps and row degrees, allocate exact row vectors, then populate rows in ascending stable column ID via inverse q. This is a counted O(n+m) two-pass index construction. It must NOT construct a packed BG first, call the generic checked insertion per imported coefficient, or reserve n-squared capacity.

Free blocks are grouped by their capacity1:32. Allocation searches at most32bin heads for capacity>=required; reuse before allocating. If none fits, append one256entry slab as eight32capacity free blocks. Publish its three buffers and eight initialized descriptors only after all allocations/checked conversions succeed. Slab directories and descriptor arrays may grow geometrically; these O(S) and O(Kcap) metadata copies are explicitly budgeted. Existing coefficient slabs never grow or copy merely because another slab is appended. Deletion leaves a block reusable, not a retained coefficient owner elsewhere. All slabs/metadata high-water capacity remain owned until refactor in this first version: no mid-update slab reclamation, coalescing allocator or compaction. This simplifies failure/handle correctness but is a real memory risk, not free space reclamation.

Row capacity growth: required+min(8,max(1,old_capacity div8)), with checked Int and Int32 boundaries. Allocate a private replacement before publication, preserve sequence and set gap at insertion cursor, then repair row_back for moved entries. A non-growing gap move touches only crossed handles. No full matrix row-index rebuild. Once old capacity>=64, spare growth is capped at8: f repeated fills starting at degree d can cause Theta(f*d+f^2) cumulative copied handles and corresponding backref repairs. Linear gap traversal within an elimination excludes this reserve/growth cost. Test repeated fills and report this tradeoff explicitly; do not silently change the growth rule after outcomes. No deletion shrinking during updates. Copy and refactor include retained row/slab/descriptor capacities.

## Mutation and numerical contract

Each completed storage primitive leaves descriptors, block order, row gap buffers and reverse references mutually consistent. Full checker is test-only. Pre-reserve all needed row/slab/descriptor capacity and stage block values before a primitive publishes numeric/index mutation; validate local coordinates/neighbor/capacity conditions, then use a nonallocating commit. Allocation failure may leave newly reserved UNUSED owned capacity after an earlier successful reserve, but must preserve live coefficients/order/references; full refactor failure preserves all prior published factor owners. Do not falsely promise byte-identical capacity rollback for update preparation.

1. **Column replacement:** preserve reference spike/prepared-cache checks and basis maps. Remove old column incidences, recycling its blocks; scan dense spike in logical-row order, skip only exact zeros as before, append ordered blocks, insert row handles by stable column ID, then rotate column maps as before. Capture each next block before recycling. Row-gap searches/moves are real O(degree(row)) costs per affected row, not O(1) replacement. No solving through a partially updated factor after failure.
2. **Entry changes:** existing value replacement does not move storage; exact-zero update removes the entry, shifts the remainder of that block by at most31 and repairs moved row handles. Gap deletion removes corresponding row handle and adjusts moved row_back. Filling a nonfull block shifts at most31entries. If its extent is too small but count<32, move the whole block to a reusable extent of adequate capacity, or a fresh32block, retaining its descriptor ID and returning the old extent through a separate free descriptor. All descriptors needed for this swap are reserved first. A full32block insertion stages33entries then splits into ordered16/17 live prefixes; reuse the old32extent and reserve one other32extent. Rebind row handles for both blocks. Never copy a full column or arena for a single fill.
3. **Local merge:** after deletion, at most the affected block and its immediate next neighbor may merge when their combined count fits max(capacity_left,capacity_right)<=32. Reuse the larger extent/descriptor, preserve concatenated logical-row order, repair handles and recycle the other block. No cascading sweep or global compaction. Empty blocks unlink and recycle immediately. Shape/order tests must cover a retained right descriptor, endpoints and nonidentity q.
4. **Adjacent row swap:** merge the two physical row incidence sequences by stable column ID. If both rows occur, their positions are adjacent in that column; swap their complete value/row/back tuples, even across a block boundary, and repair the two row handles. Single-row occurrences need no move. Swap row maps afterward. Arithmetic/pivot order is unchanged. Incidence membership remains on physical rows.
5. **Pure row rotation:** preserve reference predicate/batching. For each occurrence of the moving physical row, move its tuple through the affected column interval, block by block, repairing handles. Rotate maps afterward. This can move O(interval entries) per affected column and is deliberately NOT claimed constant time; do not create a growing chain of singleton blocks to avoid movement.
6. **Elimination:** consume source and target row incidence sequences in ascending stable column ID, filtering logical column positions as reference. Obtain value locations directly from handles; preserve old-multiplier*source, pivot, exact-zero and finite checks and history order. Source sequence membership is unchanged, but its handles may be repaired by a column block edit, so reload them after mutation; never retain stale descriptor/offset across an edit. Target's gap advances monotonically in this merge, making gap movement amortized O(source degree+target degree+fill) per elimination, plus O(32) moved entries per structural edit and occasional row/descriptor growth. Equality, deletion, insertion and split cases advance cursors explicitly; no repeated search from row start. Use the source location as the adjacent-row insertion predecessor; Task2 must not route every fill through a searching generic _bgu_set!.
7. **FTRAN/BTRAN:** traverse logical columns in original order and each block's live prefix in ascending logical-row order. Slab/extent lookup occurs once per block; inner loop reads contiguous values and row IDs. Locate diagonal from the last block when valid, with original missing/Hessenberg fallback; exclude a proven last diagonal once rather than branch per coefficient. Preserve operation order, division, signed zero and original fallback behavior. No solve-time packing, mirror, full validation or row-index scan. Bounds-check elision is permissible only inside a proven private extent; no safeguard removal.

## Memory budget — required, not promised

Let C=sum coefficient slab capacities; R=sum row incidence vector capacities; K=descriptor ARRAY capacity including free/unused slots; S=slab count; n=dimension. Three slab payloads cost16C, row handles4R, seven descriptor arrays28K, four maps+two column endpoints+two gap arrays32n, bin heads128 and block scratch528. Thus core element payload P=16C+4R+28K+32n+656 bytes. Handle width limits and every multiplication/addition are checked; no assumption that n alone bounds fill.

C initially m and grows in256entry slabs; K initially K0 and grows max(required,K+max(K div2,8)); R grows independently by the fixed row rule. Account for the outer pointer payload8n+24S, Vector/Memory headers for n row buffers,3S slab buffers,7descriptor arrays,8map/gap arrays, bins,scratch and outer directories; struct/scalar fields, directory backing spare capacity, histories/caches/work/base lower/native data are ADDITIONAL. Record actual backing capacity, not just length. Free extents consume C and K even if count0. No20bytes/live upper bound is claimed: that expression omits descriptors, gap/slab reserve, headers and manager state.
