## Representation and alternatives

Choose one contiguous structure-of-arrays slot arena with intrusive doubly linked row and column lists. Reject per-coefficient heap objects/dictionaries (allocation and lookup overhead); defer unsorted adjacency plus repeated sort/compaction (would add traversal/order work). Keeping packed columns with spare capacity would reduce growth but retain element shifts and does not implement the selected shared-slot design.

`BGSlotUpper` contains seven equal-length arrays: Float64 value; Int row_id, column_id, row_prev, row_next, column_prev, column_next. Slots1:C are allocated capacity,0 is the null link. row_id==0 marks a free slot; its column_next is the free-list link and other metadata is zero. Every live slot belongs to exactly one row list and one column list; a coefficient has one stored value. No external/public slot handles. Internal handles are valid only within the current primitive/update and must not escape into histories or prepared caches.

Rows have stable physical identities1:n. Stable column IDs are ORIGINAL BASIS positions, exactly the exported permutation q[j] for logical CSC column j; they are not renumbered to j. Initialize column_order=copy(q), column_position=invperm(q), and identity row maps. Validate q as a dimension-matching permutation before publication; invalid q is rejected. These two owned column maps are already in the eight-vector ledger, not additional maps. row_order/row_position and column_order/column_position are inverse logical/physical maps. Row lists are keyed by row_id and sorted by ascending stable column_id, exactly matching old `columns_by_row` elimination order. Column lists are keyed by column_id and sorted by current logical row_position, exactly matching old packed upper solve order. Each list has head/tail (four n-vectors total). Store live_count,free_head,capacity and dimension as scalars. No second coefficient array, full pair dictionary, per-row Vector or redundant incidence table.

Diagonal values are resolved from column lists using logical row positions, without assuming every intermediate column is triangular: a valid BG Hessenberg column may include row j+1. Missing coefficients read positive zero; imported explicit zeros, including signed zero, are preserved until the old algorithm would remove/replace them. Setting a mutated coefficient to either exact zero deletes its slot, matching old `_set_upper_value_at!`; no tolerance-based dropping. No implicit unit diagonal, reordered summation or FMA substitution.

Initial capacity is max(live_count,16) for nonempty storage,0 for dimension0. Reuse free slots before growing. Growth reserves max(required,C+max(C div2,16)) slots using checked integer arithmetic; allocate/copy all seven arrays privately before replacing the arena buffers. Preserve every live/free ID and links, no compaction. Partial allocation failure leaves the old arena intact. Actual backing capacities/headers are additionally measured: the formula is a requested capacity policy, not a Julia allocator guarantee. Deletion does not shrink during updates. Full refactor builds a separate fresh arena sized from its new export, so a much denser old high-water arena is released at publication. No retained spare arena in this version. No unconditional n-squared reservation.

## Mutation and traversal algorithms

1. **Construction:** new private dynamic factory follows the accepted direct factorize/export/check/normalization pipeline exactly, then builds the arena directly from the owned normalized CSC U. Do NOT first construct a packed BG and copy it. Pass exported q unchanged to `_bg_slots(U,q)`; iterate stable column_id=1:n through column_position (inverse q), selecting CSC column j=column_position[column_id]. Within that column visit stored rows in ascending logical row order. Append its slots to the column list keyed by column_id, and to the row lists in ascending column_id. This q-aware build preserves reference elimination order for nonidentity q while logical materialization through column_order reproduces the original CSC U. Do not change arithmetic order by assigning stable IDs from CSC order. Computing inverse q and maps is O(n). O(n+nnzU), seven arena buffers plus eight map/head vectors. Existing CSC temporary/export and normalization costs stay included.
2. **Whole-column replacement:** preserve original spike preparation, validation, and column permutation. Unlink old column slots from both indexes into the free list, scan the unchanged dense spike in ascending logical row order, insert exact nonzeros. Row-list insertion may search by column_id; column insertion is append in row order. This retains O(n+old column degree+row-search work), not O(1) replacement. Capture needed numeric/spike information before deleting old entries. No materialized packed upper or full U scan.
3. **Adjacent row swap:** merge the two stable row lists in ascending column_id. If both rows occur in a column, exchange their adjacent column-list node positions with link rewrites; if only one occurs, its relative ordering with all other rows is unchanged. Swap only logical row maps; physical row heads and slot row IDs stay fixed. O(degree(rowA)+degree(rowB)), no coefficient/value shifts. Apply original pivot comparison before the swap.
4. **Pure row rotation:** preserve original `_last_pure_bartels_golub_swap` predicate and batching. For each slot of the moving physical row, detach/reinsert that node after the nodes whose old logical positions are in the rotated interval, then rotate maps. Other physical rows follow implicitly. Searching each affected column's interval and O(rotation length) map updates are real costs. No claim of constant-time rotation or unchanged numeric operation counts from pointer savings.
5. **Elimination:** preserve pivot, multiplier=old/pivot, exact-zero branches, `old-multiplier*value`, `_track_upper_value!` effects and history append order. Merge pivot and target physical row lists by stable column_id, filtering columns with logical position greater than pivot. Existing target value is addressed by its slot, not searched in packed columns. When a target is absent, its column insertion position is immediately after the source slot because the target logical row is adjacent; row insertion predecessor comes from the merge. Save next links before deletion/insertion; source and target rows are distinct. Reserve a slot before linking it into either index. No row dictionary, whole-vector clear, repeated row scan per coefficient, or whole-column shift in this inner loop. Per elimination O(source row degree+target row degree) traversal plus fill allocations when capacity grows; the total remains dependent on fill and elimination count.
6. **FTRAN/BTRAN:** enumerate logical columns in the same descending/ascending order and traverse column links in the same ascending logical-row order as the old stable packed solve. Preserve diagonal division and exact floating evaluation order. Pointer chasing is a material locality risk. Do not sort, pack, copy, repair or validate the full structure on each solve. Solve work O(n+visited nnzU+existing history work).

The full structural checker is test-only O(n+C), proving both index traversals, unique pairs, ordering, reciprocal links, map inverses and disjoint exhaustive free/live partition. Local primitive preconditions check supplied neighbors; do not add an O(nnzU) checker to each hot mutation.

Create a new diagnostic-only `DynamicBGFactor{F}` distinct from `BartelsGolubFactorization` and NOT a subtype of `AbstractTriangularBasisFactorization`. No global overwrite or modification of ordinary dispatch/unions. Do not silently lose cache/alias/exception checks by bypassing those helpers.

Fields: existing DirectLowerBackend as base; BGSlotUpper as upper (maps owned here); updates/recycled_updates/shared_update_count with the existing BartelsGolubUpdate representation; private work/spike Float64 vectors; existing TriangularRowCache{Float64}. Use qualified private helpers with source inverse maps; no sparse workspace or public controller in this first prototype. Dense Vector{Float64} FTRAN/BTRAN and replacement are supported. Reject indexed sparse/auto interfaces and non-Float64 inputs explicitly before work; do not allow a hidden dense adapter/materialization. Other managers and all ordinary supported precisions remain untouched.

The private factory `_dynamic_bg_factor(B::AbstractMatrix{Float64},backend::Val,policy::_NativePivotPolicy)` accepts exactly native/threshold_one and Markowitz/default; reject other arms before factorization. Both reference and candidate use the same accepted factorization/export/normalization policy and genuine backend controls. Successful refactor builds an entire new dynamic candidate before publishing; old state/copies survive factorization/export/normalization/allocation failure. It preserves selected policy and normalization intent. This version intentionally does not fix repeated full-manager construction. Failed update is not promised transactional by the old contract: preserve arithmetic exception type/check order, no success history publication, invalidate caches, keep completed storage primitives structurally consistent.
