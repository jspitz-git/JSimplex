## Evidence and alternatives

The direct policy-adapter cost run compares ordinary and packed DIRECT FT/SS/BG: all24 first cells fail time/allocation gates. Saved BG/Markowitz dense96 side medians show refactors106.9/104.6 microseconds for the direct arm versus39.6/37.0 for ordinary; these nested medians are not additive and do not attribute the excess to any one allocation. Later SplitBG compares against packed DIRECT BG, not ordinary BG. Its sparse regressions remain and dense96 gains do not establish a production win. No multiplication of ratios across runs.

Source: direct-factor.jl `_direct_refactorize_with_exporter!` calls the whole constructor, which factorizes, exports, normalizes, copies U into packed columns and creates new scratch/history/cache. `factor-export.jl` allocates permutation validation scratch, creates a fresh HHExtractWorkspace and, on native export, orientation work vectors. Successful normalization creates an extra Float64 vector of length nnz(U), copies it back to CSC U, then the importer copies those values into packed columns. Native extraction converts CSR L to owned CSC; Markowitz extraction makes triplets and CSC. Those extraction paths and mandatory factorization work are not free.

Three alternatives were considered:
1. Retain a whole numerical backend and a second full output slot. Potentially largest reuse, but adds native/workspace/pool retention and copy-sharing/failed-refactor obligations. This is NOT included in this first design, and native symbolic reuse remains disabled.
2. Reuse scratch only while leaving all conversions intact. Ownership is straightforward, but saving a few small allocations alone is an insufficient performance hypothesis.
3. Selected: bounded private validation/orientation scratch plus a fused normalized import into newly owned packed U. Remove the nnz(U)-sized normalization temporary and two value-copy passes on the successful path. Keep original factor extraction and a private complete replacement object. This is a smaller, falsifiable change and does not claim to cure the whole direct-BG performance gap.

Native CSR scratch, Markowitz triplets, complete backend/workspace retention, direct Markowitz-to-packed export, custom sparse assembly, row/column format changes and active output reuse are deferred. The existing Markowitz extractor ignores HHExtractWorkspace, so merely retaining that object would not help Markowitz. The selected fused importer benefits both backends. No proposal to weaken checks or to overwrite a live factor to save memory.

## Ownership and publication

The active inner manager and saved copies never alias workspace arrays or partially built outputs. Extracted L/U/p/q/scaling remain fresh owned results. Raw U is read-only to the new importer; the exported object is never published as a mutable borrowed view. Published L and the lower backend's immutable metadata retain existing sharing rules; upper columns/work/spike/cache retain the existing copy contract.

At setup/refactor acquire a cold busy guard before scratch mutation. Reentrant refactor/copy of the same busy owner rejects before touching active state; no thread-safety promise is added. In finally clear busy. On exception release workspace (set nothing), preserve active inner identity and all its field values/owners, propagate the original exception, and publish no history/cache/success state. On successful refactor build and type-check a complete new inner, then replace only the wrapper's inner field. Workspace content may change; it is private nonsemantic scratch, with no rollback promise. No arithmetic after publication is required. Allocation failure while building scratch or output is covered by the same rule.

A successful refactor invalidates the old prepared state by replacing the whole inner, as the frozen direct path does. Existing entering-FTRAN / separate DSE-FTRAN / update provenance remains unchanged between refactors. Copy starts with no workspace rather than sharing or duplicating cache. Refactoring either copy cannot mutate the other's factors. Fallback export (`nothing`), empty dimension and unsupported transitions release workspace; fallback inner owns the ordinary backend exactly as before. No new hidden retry or extra factorization on fallback.

## Bounded reusable scratch

All retention decisions occur at export/import boundaries, never during FTRAN/BTRAN. After both triangle validations succeed, let n=size(U,1), l=nnz(L), u=nnz(U) and `P0=16*(l+u)+8*(n+1)` using checked arithmetic. P0 is a lower bound on fixed live index/value payload of the supported packed Float64/Int representation, not a full graph size. The retention charge budget is `B=min(1048576,fld(P0,16))` bytes.

Charge a nonempty workspace512 bytes plus 8*cld(n,64) for seen and 32*n for the all-or-none four-vector orientation group. The512 charge is a conservative policy allowance, NOT a proof of Julia header/allocator size. Actual reachable graph is measured separately. If B<512, retain no workspace. Prefer seen, then the orientation group only if the resulting charge fits B. Never retain a partial orientation group. Dimension change or a smaller current budget drops incompatible old buffers before allocating replacements; exact-length reuse only, no resize!/sizehint! capacity credit. Same dimension and fitting charge reuses owner identities. Checked budget overflow rejects before scratch writes; ordinary valid-size paths preserve numerical error behavior.

`_bgx_scratch!(owner, role::Symbol,n::Int,l::Int,u::Int)` accepts only :seen; orientation uses staged acquisition within the private `_bgx_scale_mode` helper described below. It returns existing or freshly allocated exact-size seen scratch. A buffer that does not fit is temporary for this call and never attached to the owner. Task1 must avoid allocating an empty workspace when nothing fits, and must not allocate discarded eligible buffers twice. All old buffers are released at most once per export boundary; invalid backend/schema input cannot retain arbitrary arrays. No full graph scan determines eligibility.

Permutation checks retain both original fill!(seen,false) passes and original error order. The private `_bgx_scale_mode` clone preserves the original orientation arguments and appends owner, n, l, u plus the diagnostic allocate keyword. Preserve every loop, FMA, tolerance, real ldiv! and acceptance/fallback decision. Scratch acquisition is STAGED, not an eager four-vector argument: all-unit scaling returns false before any acquisition; after the original scaling/index guards, acquire work and auxiliary in original order, then perform the original work initialization, ldiv! and finite/nonzero auxiliary guard. Only after that guard succeeds acquire permuted and transformed, in original order. An existing eligible complete group supplies these buffers at the same points without allocation. With no complete group, keep the first pair only in local variables; after both later allocations succeed atomically attach all four if eligible. Early return or exception never retains a partial pair; export fallback releases the cache and outer failure drops it as specified. If a later allocation fails, do not repeat earlier allocations. Markowitz requests no orientation buffers.

For a missing group the early native solve/auxiliary rejection path therefore requests only two length-n Float64 arrays (16*n payload), exactly like the source; the reached full path requests four (32*n). No new later-buffer allocation can precede a native solve exception or the auxiliary guard. Cached paths make zero such requests but retain the complete group until fallback/failure cleanup. All-unit paths request zero. Metadata and final output allocation ordering are separate from this preserved native ordering. Task1 must count requests via the local allocator seam and test first/second/later allocation failure, thrown ldiv!, nonfinite or all-zero auxiliary early return, all-unit scaling, successful acquisition and reuse. Synthetic boundary tests must be identified separately from genuine backend tests. Task3 includes a bounded cold/nonretained early-exit control; it may not hide these paths in successful-case averages.

Extraction still uses fresh HHExtractWorkspace as the reference; its internals and output conversions are unchanged. Existing native orientation may perform one backend solve; this design adds zero and removes none of those required solves. No orientation decision is cached across different factors/scaling.

## Fused normalized import

Keep normalization requested=false behavior: copy raw U to the same packed representation and return diagonal=nothing. For normalize=true first obtain D in the original column order, using exactly the original diagonal lookups and finite/nonzero tests. If diagonal normalization is ineligible, import raw U and return nothing as before. Export validation is not removed because it ordinarily establishes these conditions; standalone importer tests still exercise them.

Allocate final packed column indices/values with the same sizes, stable UpperRowOrder/UpperRowIndices and logical column order as `_direct_packed_upper`. Copy each row index once. Traverse raw U values in the same CSC column/slot order as `_direct_normalize_upper!`; compute `value=old/D[row]`, use the original finite and nonzero-to-zero rejection predicates, and write accepted values directly to final packed values. There is no nnz(U)-sized normalization values buffer and no write to raw U.nzval.

If any normalization value is rejected, stop normalization at the same entry and fill/overwrite all final packed values from raw U; return diagonal=nothing. Values already written are private and discarded by this overwrite. Do not refactor/solve again, drop tiny values, change rounding, alter tolerances or silently accept underflow. This fallback adds at most u raw-value writes beyond the partial normalized writes, no extra output allocation; count it separately. Final output allocations can occur earlier than in the reference, so an allocation failure's exact position is not promised identical; the same active-factor preservation and numeric fallback result are mandatory.

Before returning verify construction counters/endpoints during existing loops, not a new full invariant scan. Malformed export CSC/q is rejected by the original validator before import. Preserve all stored explicit zeros and signed-zero bits according to the exact original arithmetic, including normalized -0 and raw-mode recovery. No reordering/coalescing/zero-dropping through a new sparse constructor. Empty U, singleton, nonidentity q and core-row permutation are covered. Rejection fixtures target first/middle/last eligible off-diagonal slots: validated first/last literal CSC slots are diagonals and finite nonzero D/D=1 cannot trigger these division predicates. Invalid diagonal eligibility is tested separately at the standalone importer boundary. This design keeps fresh final output buffers; it reuses helper scratch, not active coefficients.

## Work and memory ledger

Define C=1+r factor construction/export/import events per lifecycle with r refactors, l_t/u_t/n_t live sizes at event t, and H update-history entries. Native/Markowitz factorization, export extraction, CSR-to-CSC or triplet assembly, validation scans and backend workspace creation are unchanged and explicitly charged. No claim of complete native/import allocation accounting or zero allocation.

| Frequency | Original work retained | Selected change |
|---|---|---|
| Each export | Validate L/U O(n+l+u), validate p/q O(n), scaling O(n); native scale-mode path as required | Reuse eligible exact-size seen/orientation helpers; missing orientation group requests2 arrays/16*n payload on early solve/auxiliary exit,4/32*n only when the later guard is reached; O(1) checked size/budget decisions; preserve reset passes |
| Each normalized successful import | n diagonal lookups/checks; u divisions and numeric checks; u row-index copies; final packed objects | Eliminate one u-length Float64 temporary (8*u payload), its u stores, and u stores copying it to CSC U; normalized values written once to final U |
| Ineligible normalization | Original early decision and raw output | At most u additional overwrite stores after partial normal writes; no retry/extra solve; fallback cost reported |
| Every solve/update | Original packed BG dispatch/arithmetic/history/cache | Wrapper forwarding only; zero new full scans, solves, conversions, index structures or numeric scratch |
| Copy | Original inner copy/sharing obligations | Constant wrapper; cache empty, no workspace copy |
| Refactor | Complete private replacement before publication | Retain eligible scratch across events, no backend or complete-output reuse |

On successful normalization the reference writes each U value to normalization temporary, back to raw CSC and then to packed U (3*u stores); candidate writes it once to packed U (u stores), saving2*u stores and8*u temporary payload per event. This does not remove the original CSC U or final packed U, the D vector, final column objects, export scans or arithmetic. Across C events, source temporary payload avoided is8*sum(u_t), not measured GC bytes. Repeated matching-shape eligible helper requests can be avoided after first acquisition; transient/nonmatching cases still allocate. Count actual allocator requests and metadata/tuple/wrapper costs rather than claiming exact GC events from source counts.

Let A_old and A_new be complete active and new factor graphs, E_t all extraction/conversion/backend temporaries, and W_t private retained scratch plus any transient group. Peak during refactor includes A_old+A_new+E_t+W_t; failure may leave allocated garbage until GC. Copies add their own graphs and only documented immutable sharing. The removed8*u temporary may reduce transient overlap, but runtime liveness/physical peak is not proved. Workspace charge<=B is an admission policy, not a full process/native peak bound. Newly retained workspace can increase post-refactor graph even when allocations fall; no second active factor is retained in this design. Full factor graph includes wrapper/workspace, and all intermediate/final gates must count them. Existing work vectors, prepared caches, row incidence, recycled updates and history H are not omitted. Pooled backend memory is not retained newly.

This first scope intentionally leaves backend reconstruction and many export allocations unchanged. If the observed overhead is dominated by them or by updates, the design can fail despite eliminating a real temporary. Do not combine it with the import-reserve rule, free-block changes, solve kernels, bulk column replacement or native reuse to rescue results.
