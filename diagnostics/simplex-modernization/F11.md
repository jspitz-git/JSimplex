# F11 — Scaled stagnation detection

Status: implementation, complete suites, and measurements verified.
Parent: `05ddc0e` (F10). Known reader failures and time-censored solves remain recorded.
The feature is enabled by the opt-in adaptive strategy. Legacy remains the default.

## Behavior

A fixed-size streaming monitor records window start, minimum, and endpoint
values for the working objective and primal/dual infeasibility. Two windows
without significant improvement yield `:stalled`; the first yields `:watch`.
New significant progress returns `:progress`. Sub-tolerance improvements
accumulate against the last significant reference. Nonzero or oscillating
steps alone do not establish progress. The monitor also counts insignificant
steps, using exact zero comparisons for rational arithmetic.

Working cost and variable scales normalize the observations. Arithmetic
averaging avoids overflowing sums and is canceled in the significance test.
The additive objective constant is excluded. Dual objective progress has the
opposite orientation to primal objective progress. User feasibility tolerances
mask already acceptable violations; the numerical policy controls significant
relative improvement. Rational observations use rational BigInts, never floats.
BigFloat observations use the workspace's stored precision. Diagnostic rational
price ratios also widen before division. Infinite floating-point step magnitudes
are accepted as non-small steps; nonfinite objective/feasibility metrics and
NaN steps remain invalid.

The live optimize loop advances history only after a completed step, once per
iteration. A rejected candidate cannot overwrite history. Restoring a basis or
resetting a pricing cache preserves history. Actual auxiliary phases reset it;
changes to working costs, bounds, scaling, or algorithm create a new window.
The context signature examines every value because Julia's hash for large
arrays samples entries. This requires linear work in the working-vector sizes
per observed iteration; the retained history itself has constant size.

Stalled floating-point dual steepest-edge runs that remain primal infeasible
use the existing Dantzig fallback. With the monitor disabled, the original
256-zero-step trigger remains. This feature does not add perturbation or
pricing strategies. The original later perturbation trigger remains for F12.
Diagnostics emit `stagnation_watch`, `stagnation_stalled`, and
`stagnation_fallback` events. Numerical certification and user tolerances are
unchanged.

`NAME          BLEND    BRUCE MURTAGHS BLENDING PROBLEM (MINIMIZE).`; both the F10
parent reader and the F11 reader reject the extended header with
`unexpected data; expected an MPS section`. A direct F10 reproduction passed
**2/2** checks and confirmed the parent module path. Neither the input file nor
the reader was changed to make this benchmark pass.

The first holdout CLI exited 1 because of that input error; its other four cases
completed measurements. The supervisor initially stopped on the nonzero CLI

## Final audit and decision

[Raw results](F11-results.json) retain 13 report groups, **852 solve observations**
(**840 OPTIMAL**, all original-primal-valid; **12 TIME_LIMIT**) and **two reader
failures** on the same frozen blend input. Of the solve observations, 112 are
explicitly reused original-reference samples and 740 are fresh. Dataset hashes,
source hashes, paired completed objectives, legacy paths, and both full-suite
exit codes passed the final artifact audit. All current-source measurements use the
same frozen F11 fingerprint above. Both holdout CLI exit codes are retained as 1
because of the reader limitation; this is not reported as an all-successful corpus.

The detector and existing fallback connection are verified, including an actual
external stagnating case. There is no new solved-model coverage and no established
broad speed or stability improvement. Keep adaptive behavior opt-in; F12–F14 can
consume the shared detector without inventing another zero-step counter.


## Interpretation limits

The harness evaluates primal residuals and objective consistency in original
model units. Its public-result interface does not expose a mapped original-model
dual witness; `OPTIMAL` remains the solver's reported status, not a new independent
dual certificate. Paired objective comparisons and the development suite's
independent reference checks provide additional evidence.

The monitor has a fixed number of retained scalar fields, not an iteration-sized
history. Exact and BigFloat scalar storage still depends on operand precision.
Every observed iteration performs linear scans of working vectors; this is
measurable overhead on small LPs. Quick-set timing alone does not demonstrate
better handling of stagnation. Adaptive behavior remains opt-in, and no broad
speed or stability milestone is claimed by the quick timing results.
