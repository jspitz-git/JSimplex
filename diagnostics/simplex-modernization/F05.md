# F05: Shared refinement of basis solves

The adaptive profile adds the independently switchable `solve_refinement` stage.
`refine_basis_solve!` evaluates componentwise backward error, then applies at
most `max_refinements` corrections using the current basis factor. It owns its
saved RHS, correction and trial storage. Normal and transposed solves share the
same acceptance logic. Failed, nonfinite, stagnant or deadline-limited attempts
retain the last accepted finite destination; they do not claim a reliable solve.

Arguments cannot alias each other, private correction/residual buffers, model
coefficients or basis assembly storage. Float32 residuals accumulate through
Float64; uncertain Float64 residuals use the existing local wide evaluation.
BigFloat correction arithmetic respects stored input precision and restores the
caller's precision context. Rational tests use exact residuals and comparisons.
A reliable backward error is not a forward-error or pivot-safety certificate.

The shared check covers basic values, costs, pivot rows/directions, pricing
solves, candidate certificate multipliers and the aggregate BFRT flip RHS.
Aggregate flips preserve the pending entering direction and apply no states or
values after an unreliable solve. An explicit internal numerical exception
routes other unreliable solves through existing numerical handling and bounded
pivot refresh. Default guards read the common solve clock without calling user
code inside a staged commit. Correction events produced during staged primal
completion are buffered until the live basis, values and prices are consistent.

The former cost, row and direction repair loops share a precision-specialized
kernel. Their existing 256/512-bit checks, absolute residual targets of 1e-40
and 1e-90, maximum 32 corrections, and independent caller validation remain.
These stronger checks are not replaced by ordinary Float64 backward-error
acceptance. They remain exceptional repair paths. Disabling solve_refinement
retains F04's pivot-specific corrections and the legacy additional checks.

## Validation

The initial missing-API test failed as expected. Shared API, range, alias,
precision and integration checks passed before the broader regression run.
The stale-factor test uses a well-conditioned fixture: an ill-conditioned
Float32 system can legitimately have a small backward error despite a large
forward error, so the fixture must not conflate these guarantees.

The initial broader regression run passed 2,729 checks. External smoke then
exposed five numerical failures in four models; those observations are retained.
The corrected focused F05/F04 run passed 607/607 checks and JET passed all 26
inference checks.
Independent 1024-bit residual checks cover the stronger 256/512-bit repairs,
nonconvergent factors, early deadlines and conversion overflow. Broader
regression coverage includes all production and development tests. The final
standard `Pkg.test()` run passed **226,126/226,126** checks in 13m38.6s; the
development suite passed **625/625**, including JET. External repeated measurements and the refinement census also passed, as
detailed below.

## Homogeneous residuals and discarded work

The first external regression came from transposed cost solves. In a captured
adlittle basis, a multiplier of about -6.94e-18 was the sole nonzero term in
otherwise zero homogeneous equations. Its componentwise error was 1.0 despite
the tiny absolute error. A stricter tolerance is not the remedy, and accepting
the existing error would violate the quality contract.

When broader refinement is enabled, uncertain Float64 residuals are reevaluated
locally at higher precision. If an ordinary finite correction remains
unreliable, refinement may clear a lone active term in an equation whose RHS
is exactly zero. Coupled floating roundoff components appearing in homogeneous
rows may also be proposed for removal when they are at most solve_tolerance
times the largest candidate component. This cutoff generates a trial; it does
not relax acceptance. The entire system is checked with the unchanged error
bound, and a worse cleanup restores the ordinary candidate. Right-hand sides
are never rounded or modified. Rational arithmetic uses no floating cutoff.
Cleanup stays inside the correction budget.

A 3x3 normal/transposed reproducer failed four assertions before this change.
A separate test preserves a small nonzero RHS. Failed staged candidates also
retain counts of correction work already performed, without sending observers
an uncommitted state; completion and bound-flip events remain uncounted when
their candidate is discarded. That counter regression failed two assertions
before the fix.

The first homogeneous cleanup improved external smoke from 11/16 to 13/16
OPTIMAL outcomes; three numerical regressions remained. A coupled 3x3 case
then reproduced four failures. Independent evaluation of eight captured
adlittle failures showed that joint cleanup satisfies the original bound.
The extended cleanup also has a regression requiring restoration of real small
components needed by another nonzero RHS. The corrected smoke passed all 16 solves with original-primal validation.
Full-suite validation and final repeated measurements passed.

## External comparison and limitations

The original d93cfd3 solver, F04 adaptive parent, current legacy, current adaptive
with `solve_refinement = false`, and full adaptive each completed **112/112
OPTIMAL** samples. The eight frozen NetLib/MIPLib cases ran both algorithms
seven times with a 60-second per-solve budget. MIPLib cases were explicit LP
relaxations. Every sample passed original-model primal validation and adaptive
objectives agreed with both reference revisions within
`max(1e-7, 1e-9*abs(objective))`.

Disabling the new stage exactly reproduced the F04 adaptive objectives,
iteration counts and refactorizations. Current legacy exactly reproduced the
previous legacy observations. Neither default behavior nor user tolerances
changed.

The geometric mean of per-case median time ratios against F04 adaptive was
**1.430 for primal** and **0.811 for dual**. Against the original d93cfd3 solver,
the ratios were **2.919 for primal** and **1.632 for dual**. Ablation ratios
against F04 were 1.065 and 1.044. These short warmed measurements show a mixed
tradeoff, not a general speedup. The adaptive profile remains opt-in; it does
not yet meet the final default-selection performance gate.
