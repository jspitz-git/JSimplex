The new internal `NumericalPolicy{T}` separates basis solve quality and pivot
error from the user's primal/dual feasibility tolerances. `simplex_strategy`
is propagated through SolverOptions, scalar conversions, remaining budgets,
MOI, the internal solve context, and progress contexts used by retries and
cleanup. Its default is `:legacy`. The opt-in `:adaptive` profile enables no
algorithm stage yet; enabling an unimplemented stage is an error.

Initial policy limits are 3 solve refinements, 8 pivot candidates, 2 recovery
rounds, a 64-step stagnation window, 512 working precision bits, and 8 LP
refinements. The initial floating solve limit is `256eps(T)` and the separate
pivot error tolerance is `sqrt(eps(T))`. Exact rational limits are zero. These
are internal experimental limits and do not change certification tolerances.

`solve_quality!` computes `rhs - B*x` or `rhs - transpose(B)*x` and the
componentwise scale `abs(rhs) + abs(B)*abs(x)`. Its scratch is separate from
live tableau storage; aliasing the basis, RHS, or solution is rejected before
mutation. Float32 accumulates through Float64. Unsafe range, subnormal products,
or an excessive summation-roundoff bound trigger local BigFloat evaluation.
BigFloat evaluation respects actually stored input and policy precision and
uses additional guard bits. The return value includes the computed absolute
residual, componentwise relative error, finiteness, and reliability with a
conservative residual/scale-roundoff allowance. A zero scale contributes zero
only for a zero residual. Exact rationals check the residual exactly and have
no floating relative-error value. A small backward error does not certify a
small forward error or a safe pivot in an ill-conditioned system.

Numerical policy overrides are accepted by the development runner, validated
by the selected source, and recorded with the source identity. Snapshots and
traces retain their effective policy. Replay retains the saved strategy and
can override internal policy values. Old source checkouts remain benchmarkable
with legacy defaults. Serialized snapshots require a matching source layout.
Policy files, like model inputs, cannot be used as report destinations.

MOI reset is interpreted as constructing a fresh optimizer. `MOI.empty!`
preserves the numerical strategy, as the adapter's existing tests explicitly
require for other optimizer options. A fresh optimizer restores `:legacy`;
callers can also set that value explicitly. Resetting only this one option on
`empty!` would violate the existing lifecycle contract.

No numerical algorithm has been enabled or user tolerance weakened in F02.

## Reproduction

Use the offline Julia 1.13 environment and depot from the F01 report.

```bash
julia --startup-file=no --project=. -e 'using Pkg; Pkg.test()'
julia --startup-file=no --project=dev dev/tests/runtests.jl
julia --startup-file=no --project=dev dev/simplex_benchmarks.jl --source=SOURCE --suite=quick --algorithm=both --samples=7 --time-limit=60 --iteration-limit=100000 --diagnostics=off --simplex-strategy=STRATEGY --output=REPORT.toml
git diff --check
```

The measured variants are the parent with legacy defaults, F02 legacy, and
F02 adaptive. No benchmark runs concurrently with tests. F01 original-source
results are retained for status/objective/iteration comparison; F02 does not
claim a fresh original-revision timing comparison. Each new report records
effective policy, selected source, dataset hashes, and original-unit errors.
