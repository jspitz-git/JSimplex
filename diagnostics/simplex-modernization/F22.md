# F22 — Typed transfer across working precisions

Complete production, development, inference and external-model validation passed.
Automatic precision recovery remains a separate opt-in feature for F23.

Parent: `ca07720` (F21). Production source SHA-256:
`b83453b04eab61246eeec7d9607c39a22aa106095fff6a163f183b134879c3eb`.

## Implementation

`copy_working_values(S, values; bits)` copies numeric vectors, bound vectors and
sparse CSC matrices into owned storage. Float32 to Float64 and Float64 to BigFloat
preserve the stored binary values. BigFloat precision is at least the requested
precision and the highest stored input precision. Unbounded `Bound` values retain
their tags. Floating downcasts and transitions between rational and floating
arithmetic are rejected. Exact rational copies remain exact.

`transfer_precision(ws, S, bits, budget, policy)` builds a new concretely typed
workspace and factors the actual transferred basis. It assembles only selected
sparse columns, including activity columns, and avoids constructing an unrelated
slack factor first. The resulting factor, primal values, prices and pricing
weights are rebuilt and checked. The old factor is never wrapped as a higher
precision factor or assigned to a workspace with incompatible type parameters.

The precision scan includes matrix coefficients, original and working costs,
objective constants, original and working finite bounds, progress objectives,
scaling factors, user tolerances, numerical policy tolerances and perturbation
snapshots. Conversion/factorization run inside a local precision scope. Explicit
policy flags and limits are preserved instead of reconstructed from defaults.
The original progress clock, scaling context and outer retry offsets survive.
Canonical exact binary model-content checks compare values across storage types;
the old model and its arrays remain unchanged.

Perturbation journals receive a new workspace owner and independent original and
active buffers. Restoring a transferred journal cannot modify the old workspace.
Attempt levels and cooldowns survive. Old monitor histories, row indices, pricing
storage and checkpoint identities are discarded; verified checkpoints may be
created for the new model during recomputation. Actual steepest-edge weights are
rebuilt for the new inverse; devex storage is reset.

Transfer preserves cumulative iterations and refactorizations. Every attempted
new factor, including a failed one, consumes the shared refactorization count.
Cancellation returns `nothing`, including cancellation after a completed factor;
invalid basis states and numerical construction failures throw. Caller and
observer exceptions retain their identity/provenance. The original numerical
state remains intact while consumed counters advance.

Julia's same-precision BigFloat constructor returns its argument. The copy path
therefore explicitly deep-copies that case. A new BigFloat inference check also
exposed a boxed accumulator in the existing progress-objective formatter. Binding
the previous sum locally removes dynamic dispatch without changing arithmetic
order or precision.

## Scope

This feature supplies an internal transfer operation, not automatic precision
recovery or a new public solution type. `Solution{T}` and all defaults are
unchanged. F23 adds automatic level selection, recovery integration and resource
checks for dense fallback; the result-conversion container is deferred until that
consumer needs it. The controlled transfer tests use small bases.

## Validation

The targeted suite passed 1,571 behavioral checks plus 10 new JET checks. It covers
Float32 to Float64, Float64 to BigFloat, wider BigFloat and exact rational copies;
all four basis-update methods and both refactorization backends; MAX sense and
constants; finite/free bounds; owned journals; scaling/progress mappings; invalid
and singular bases; callback/deadline interruption; and preserved counters.
Hidden 1,024-bit inputs in constants, progress, tolerances and journal snapshots
survive conversion requested at 128 bits under a 64-bit ambient context.

The complete JET suite passed 203/203 checks. External NetLib `afiro` and explicit
MIPLib `flugpl` LP-relaxation transfers passed 42/42 checks: Float64 bases were
rebuilt with actual BigFloat factors at 128 and 256 bits, stored coefficient/cost
values were preserved exactly, and original-model optimality was checked again.
The [external records](F22-external.toml) retain dimensions, input hashes, objectives
and factor precisions. The complete development suite passed 1,076/1,076 checks
across 62 testsets. The complete production suite passed 252,649/252,649 checks
via `Pkg.test()` in 72 minutes 8.8 seconds, including the BigFloat integrity,
options and MOI checks. The source fingerprint was unchanged throughout the
successful verification. The final audit checked all suite exits/counts and
external factor records.

No performance claim is made for this internal capability. No stress-only model
was solved or fully factorized.
