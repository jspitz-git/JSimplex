# F03: Stable Harris bound-flipping ratio test

The opt-in adaptive profile now groups nearby dual breakpoints, tries stronger
pivots first, and reconstructs bound flips at each candidate's actual step.
The legacy profile retains the previous implementation. Both ordinary and
refined dual pivot selection use the configured ratio test.

A proposal owns no live simplex state. Its flip vector borrows workspace
storage until the next proposal. Every candidate checks the resulting nonbasic
reduced costs and remaining primal displacement. Earlier boxed breakpoints do
not automatically cause flips when their price deviation remains tolerated;
optional dual-feasible flips are used only when the entering range is too
small. Free and one-sided variables retain their step restrictions. Exact
rational arithmetic uses zero relaxation and exact comparisons.

Candidates sort by breakpoint and index, then by descending pivot magnitude
within each Harris interval. Cumulative range capacity skips early intervals
that cannot repair the violation. Full-row candidate validation is bounded by
`max_pivot_candidates`. Unsafe coefficients, nonfinite arithmetic, underflowed
displacement, and exhausted validation budgets produce `:uncertain`; this
cannot be interpreted as mathematical infeasibility. Basis recovery after an
uncertain proposal is a subsequent implementation stage.

## Validation

The first new test failed because `stable_ratio` was not implemented. The
completed targeted run passed 2,000 checks across dual simplex, ratio proposals,
and NetLib/MIPLib numerical regressions. New proposal coverage includes 204
checks against independent enumeration of rational pivot/flip combinations,
all four scalar types, reversed row orientation, nearly coincident breakpoints,
optional zero-price flips, fixed/free/one-sided variables, overflow, underflow,
tolerated negative steps, deterministic ties, and safe candidate exhaustion.

The full production suite passed **225,519/225,519** checks (9m01.7s, exit 0).
The full development suite passed **623/623** checks (exit 0), including policy
propagation through an isolated adaptive worker. The tested source hash is
`8fc3b9417019c351ca20c8a96d730ad959ffed5e7d115a79ec847589849e9132`.

## External quick comparison

The parent (`fd48be1`), current legacy, and current adaptive versions each
completed **112/112 OPTIMAL** samples: eight frozen external NetLib/MIPLib
cases, both algorithms, seven repetitions. MIPLib inputs were explicit LP
relaxations. Every sample passed original-model primal validation, and adaptive
objectives agreed with the parent within `max(1e-7, 1e-9*abs(objective))`.
Legacy objectives, iterations and refactorizations matched the parent exactly.

Adaptive dual iteration counts changed as follows:

| Case | Parent | Adaptive |
| --- | ---: | ---: |
| afiro | 9 | 8 |
| adlittle | 102 | 106 |
| kb2 | 41 | 49 |
| sc50a | 34 | 34 |
| pk1 | 353 | 48 |
| flugpl | 12 | 12 |
| stein9inf | 7 | 6 |
| markshare_4_0 | 10 | 9 |

For pk1, dual refactorizations fell from 18 to 2; its median elapsed-time ratio
was 0.636 versus the parent. Across all eight cases, the geometric mean of
median time ratios was 1.006 for adaptive dual and 1.041 for adaptive primal.
Legacy ratios were 0.994 and 1.051 respectively. These short timings are noisy:
this supports the specific pk1 iteration improvement, not a general speedup
claim. The primal adlittle run changed from 117 to 118 iterations because a
primal solve can use dual simplex during its auxiliary/retry work.

## Repair replay and scope

A fresh diagnosed legacy solve of the external pk1 LP relaxation captured its
first actual repair state using the current source format. Loading that
snapshot with `stable_ratio = true` and a fresh basis factorization reached
OPTIMAL at 85 cumulative iterations. This is a result for the working snapshot
model, not a second original-model certificate or reproduction of the old
factor-update drift.

The machine-readable observations are in [F03-results.json](F03-results.json).
Raw reports and task-owned binary snapshots remain local under
`/tmp/simplex-F03-*`; external models and snapshots are not committed. The
large stress-only inputs were not solved. This feature changes pivot selection;
transactional application, pivot-quality retries and basis recovery remain
subsequent stages.
