# F17 — Reachability-based solves for base LU factors

Status: complete; all correctness gates and preset measurements passed audit. Parent: `dd9664f`.

## Behavior

`SparseTriangularFactor` owns coefficients, diagonal values, row indexing for
transpose traversal, and generation-stamped DFS scratch. Reachability visits
only exact nonzero dependencies and returns a borrowed topological order.
Numerical substitution preserves every small nonzero value; cancellation is
compacted after each operation. The first traversal can grow its private buffers;
subsequent traversals reuse their capacity.

`SparseSolveView` snapshots a single base LU, including permutations, scaling,
graphs, and any dense trailing core. Old views survive backend spare-buffer
reuse. Every view owns mutable solve scratch; concurrent solves need independent
views. Public RHS/destination aliasing is supported by gathering before output
publication; aliases of private value/support buffers are rejected.

The Markowitz adapter handles all five supported scalar types. Its operation
order is lower solve, dense-core solve, upper solve; transpose reverses this.
A reached dense core can fill its whole result. Native dense backends return
`nothing`, preserving the original solve as fallback. BigFloat execution retains
stored factor/RHS precision even under a lower ambient precision; exact rational
arithmetic never converts to floating point.

The UMFPACK adapter uses public `L`, `U`, `p`, `q`, and `Rs` properties only.
The ordinary reconstruction identity was verified with nontrivial permutations
and scaling before implementing the mapping. Extreme-scale testing then exposed
an installed-backend limitation: `Rs` can contain divisors despite documentation
describing multiplication. One public native solve checks which interpretation
matches the extracted factors. Indistinguishable or nonfinite checks decline
the adapter; no native pointers or guessed reciprocal thresholds are used.
This extra setup solve is included in adapter-construction measurements.

F17 introduces the base-factor interfaces without selecting them in simplex
iterations. F18 propagates indexed support through basis updates; F19 owns the
cached-view lifecycle and automatic per-operation sparse/dense selection. Callers
of this internal interface retain one view per base LU and rebuild it on
refactorization. The ordinary solver path and public defaults remain unchanged.

## Preset measurement protocol

Timings started only after all correctness jobs finished successfully, with
unchanged numerical source.

The generated fixture has 1024 rows, disconnected 16x16 tridiagonal blocks
(-1,4,1), a row shift, and reversed columns. Both native and Markowitz backends
receive seven fresh-LU and seven adapter-construction samples. Forward and
transpose solves use RHS supports 1, 16, and 1024. Each profile measures seven
100-call samples of the original dense solve, indexed solve with existing
support, and indexed solve including dense support discovery/output copying;
path order rotates. Adapter storage and original factor storage are reported.
The standalone worker has a 120-second limit.

A two-method adlittle smoke group uses adaptive strategy, automatic pricing,
PFI/native, clock-based refactorization disabled, 100000 steps, 60 seconds per
solve, and one sample after warmup. It checks unchanged ordinary solver behavior,
not an end-to-end speedup from the unconnected base-factor interfaces.

External components use 90-second workers and explicit read quotas: scsd8,
markshare_4_0 (LP relaxation semantics), and runtime 64 MiB; medium 128 MiB;
largo 160 MiB. Factor extraction visits at most 50000 stored entries and selects
at most 64 occupied rows and columns. Its leading square is row-normalized and
made strictly diagonally dominant before bounded factorization. These synthetic
components are not bases of the original LP and never count as solved coverage.
The original F16 leading-block pricing probe remains separate.

Big/largo/AnyMOD receive 1 MiB pre-parse quota checks, and big/AnyMOD bounded prefix
inspection. None receives full-sized basis factorization or a complete simplex
solve. All workers request 24576 MiB, clipped to available physical memory.
No complete runtime/medium solve is scheduled here; later full runtime runs
retain at least 360 seconds per solve. Cold external setup can include compilation;
generated timings warm their kernels. Array/storage sizes, allocations, and RSS
are distinct measurements.

## Interpretation and limits

Both ordinary adlittle smoke solves returned OPTIMAL with original-model primal
certification and exactly the F16 disabled-arm objective, iteration count, and
refactorization count. Neither public result exposes an original-model dual
witness. The single primal sample includes 0.205320 seconds of GC within its
0.310893-second total; it is not a speed comparison. Peak process RSS was
1,892,708,352 bytes for both samples.

On the generated component, a unit RHS grows to 16 nonzeros and indexed solves
including conversions are about 4.6–6.3x faster than the existing dense solves.
At support 16 the result grows to 256 nonzeros: native solves and Markowitz
transpose lose their advantage after conversions, while Markowitz forward still
improves. Fully dense results are about 4.9–6.7x slower with indexed conversions.
All 252 warmed call-time observations allocate zero bytes per call. Adapter
construction costs approximately 103 microseconds for native and 56.5 for
Markowitz, in addition to the original LU; retained view storage is about
285 kilobytes. These are component observations, not an end-to-end LP speedup
or evidence of broader solved coverage. F19 must retain independent dense paths.

All five external component groups completed and verified both solve directions
for both backends. The occupied selection fixes the F16 empty-block limitation:
runtime and medium each contribute 64 stored entries, and largo contributes 108.
These remain small, normalized, diagonally-dominant synthetic components. In
particular the runtime/medium blocks are very sparse and do not characterize
fill-in or the memory required by a complete original-model basis. Cold external
setup can include compilation. Their reported storage and allocations are not
process peak RSS.

Three 1 MiB quota guards returned resource_stop before full hashing/parsing, and
two prefix inspections completed as partial_inspection. All worker memory requests
were clipped to 25,141,338,112 bytes. Oversized-model component/protection results
are excluded from LP coverage and solve speed scores. No runtime/medium complete
solve or full-sized factorization of any excluded model was performed.
