# F16 — Indexed vectors and sparse row pricing

Status: complete; all correctness gates and preset measurements passed audit. Parent: `48f3a28`.

## Behavior and ownership

`IndexedVector{T}` owns dense values, candidate support indices, and generation
stamps. Cancellation can leave a zero index until compaction; reinsertion never
duplicates it. Clearing visits stored support, with an explicit generation-wrap
reset. Only exact zeros are omitted, and stored zero signs are normalized.
The dense view is borrowed for reading; mutation goes through helpers. A failed
conversion or arithmetic operation can leave a partial result, but its support
remains coherent and clearable. Floating overflow is rejected; rational arithmetic
never converts to floating point. BigFloat addition preserves the highest stored
operand precision.

`RowAccess` owns immutable-by-contract row metadata and references CSC values by
position instead of copying them. It caches matrix precision once. Active RHS
rows are processed in increasing order so each canonical CSC column retains its
nonzero summation order, including fixed-width rational intermediate behavior.
Noncanonical custom CSC storage uses the independent CSC accumulation order.
The slack output is `-rho`. BigFloat pricing respects stored matrix/RHS precision
under a lower ambient context. Small nonzero entries are never dropped by a
numerical tolerance.

Workspace RHS/output/ordering buffers are lazy and independently owned by live
and staged computations. Read-only row metadata can be shared for the same
immutable working matrix. Model/dimension/type changes require fresh indexing;
phase/checkpoint invalidation clears both live and staged caches. A valid staged
cache is retained when the live workspace has never requested row pricing.
Pricing the weight-update row does not overwrite a concurrently live tableau row.
There is no global cache keyed by matrix identity.

The independent CSC pricing path remains available. The internal
`sparse_pricing=true` switch enables row pricing, but defaults to false for both
legacy and adaptive strategies. F19 owns automatic sparse/dense selection and
the complete sparse solve/update pipeline. F16's dense-to-indexed discovery and
dense output copying remain real costs and are included in its measurements.
The optional `row_index` kernel timer records lazy index construction inside
pricing; its time is nested, not additive to the pricing timer.

## Preset measurements and bounded stress

Same-source short-solve ablations use adaptive strategy, automatic pricing,
Float64, PFI/native, fixed F15 switches, clock-based refactorization disabled,
100000 iterations, 60s per solve, and 24576MiB requested memory. Adlittle gets
seven uninstrumented samples and one diagnostic sample per method/arm: 32
observations in four groups. Each method receives one uninstrumented warmup;
diagnostic samples add an instrumented warmup.

The standalone component benchmark uses a fixed 1024x2048 matrix with eight
entries per column. It records seven index-construction samples and seven
100-call samples per path for supports 1, 16, and 1024. Indexed timing includes
RHS support discovery and copying back to a dense consumer. Construction is
reported separately and included in the short complete solves. This generated
matrix provides component evidence, not independent external solved coverage.

External stress probes use explicit 60s worker, memory, and read-byte quotas.
After bounded parsing they extract at most 256x256 with at most 50000 stored
entries; row indexing, unit/quarter/dense RHS pricing, and cancellation are
checked without constructing a simplex workspace or factorization. External
component setup is cold and may include compilation; the standalone generated
component comparison warms the kernels before collecting its repeated samples. The runner
records the component helper's source hash and distinguishes component errors
from reader errors. Index/scratch byte counts describe active arrays; process
RSS and cumulative allocated bytes are different quantities. Short-solve peak
process RSS ranged from 1,858,928,640 to 1,978,322,944 bytes. External component
probes report active-array sizes and allocations, not process peak RSS. The
24576 MiB request was clipped to the host physical-memory allowance of
25,141,338,112 bytes; no default 4 GiB worker limit was used.

The preset component cases are NetLib scsd8, MIPLib markshare_4_0 (explicit LP
relaxation semantics), and local runtime, medium, and largo. Big/largo/AnyMOD also
receive 1MiB pre-parse quota guards; big and AnyMOD receive bounded prefix
inspections. None of these three oversized models receives a full-sized basis
factorization or a complete simplex solve. Resource stops remain in the report.
No full runtime/medium solve is scheduled for F16; later complete runtime runs
retain at least 360s per solve and the 24576MiB memory request.

All 32 short-solve observations returned OPTIMAL and passed original-model
primal certification. The disabled arm reproduces F15's adaptive adlittle
iteration/refactorization counts and objective. Both arms follow the same work
counts here; their approximately +2.1% primal / -3.0% dual median time changes
do not establish a broad end-to-end improvement.

The generated component gives approximately 10.4x and 4.7x faster pricing for
supports 1 and 16, but approximately 7.1x slower pricing for dense support.
Both warmed paths allocate zero bytes per measured Float64 call. Index setup,
support discovery, and output copying are accounted for. These results motivate
F19's per-operation dense fallback; they do not justify enabling the experimental
switch for all solves. Legacy remains the public default.

All four diagnostic observations expose mapped dual witnesses. Strict dual-sign
errors are 9.5793e-13 for primal and 1.4092e-12 for dual in both arms; the strict
complementarity diagnostic is Inf for each. These raw diagnostics are preserved,
not rounded into exact dual feasibility. The other 28 observations do not expose
a mapped original-model dual witness. No new independent solved-LP coverage is
claimed.

Five bounded component groups completed, three pre-parse quota guards stopped
as intended, and two prefix inspections completed within their byte limit.
The selected top-left runtime and largo blocks contain zero stored entries;
those observations validate parsing, empty row structure, slack pricing, and
support cancellation, not nonzero-matrix arithmetic or large-LP solution speed.
Medium's extracted block has 243 stored entries and completed within the memory
allowance. No conclusion about full medium/runtime factorization memory or solve
time follows from these bounded probes.

For each short-solve arm, create a policy TOML containing
`refactor_timing = false` and either `sparse_pricing = false` (CSC) or
`sparse_pricing = true` (indexed). The timing command is:

```bash
julia --startup-file=no --project=dev dev/simplex_benchmarks.jl \
  --source=. --file=/home/jspitz/NetLib/adlittle.mps --algorithm=both \
  --simplex-strategy=adaptive --pricing=auto --basis-update=pfi \
  --iteration-limit=100000 --time-limit=60 --memory-limit-mib=24576 \
  --policy=/tmp/F16-policy.toml --samples=7 --diagnostics=off \
  --output=/tmp/F16-adlittle.toml
```

The census replaces the last sample/diagnostic options with
`--samples=1 --diagnostics=on --kernel-timing=on`. Bounded component runs use
`--mode=stress --stress-operation=components --read-limit-mib=QUOTA` with the
same 60-second worker and memory limits. The preset read quotas in MiB are
64 for scsd8/markshare/runtime, 128 for medium, and 160 for largo; separate
pre-parse guards use 1 MiB. Prefix probes use `--stress-operation=inspect`.
These commands do not schedule complete solves of the oversized models.
