## Work per proposal

choose_leaving scans exact infeasible-basic membership once (at most m); robust scaled Devex score, deterministic row-ID ties and generation-bound rejected rows, no heap/cache. Rejection cleanup visits its previous used prefix, not a new full m pass. At most8 rejected rows route to recovery. Complete nonzero tableau support s is used to build breakpoints and finite gains. Sorting is explicit in-place QuickSort of used prefixes: O(s log s) main breakpoints, Harris group strength sorting and optional flips; no full support sort or new N coefficient copy.

Each of at most8 mathematical ratio-candidate validations visits complete support, including every potentially changed nonbasic price and every mandatory/optional flip; maintained dual_bad membership must be empty before entry, so outside-support invalid prices cannot disappear. Box widths, finite products/sums, underflowed positive capacity, cutoff-ineligible sign candidates and uncertain exhaustion remain guarded. Exhausted is not an infeasibility certificate. No per-candidate N scan, support construction, factor copy or repeated BTRAN.

Successful no-flip proposal uses1BTRAN+1FTRAN; flips add exactly one aggregate BFRT FTRAN, with entering direction retained separately. Original complete row residual remains charged. Direction and BFRT have independent complete marked-row residual/scale checks; BFRT uses pivot0 to retain the zero/roundoff criteria without borrowing the entering pivot allowance. _pivot_agrees uses the unchanged policy-derived bound. Failed validation/planning expires its stage; it cannot silently repeat solves/planned writes under the same proposal.

Devex reference sum visits complete tableau support; basic weights visit entering-direction support plus entering index. Primal union is direction/BFRT support plus flips/entering/leaving. Reduced prices visit complete tableau support plus entering/leaving; entering backward-price correction is a pending cost shift. Each changed numeric field is planned once with finite/positive checks; unchanged exact values are omitted. Mask/stamp union construction is constant work per planned ID, including zero-step state changes. Repeated successful validate/plan queries only verify provenance; they do not solve or write again. Fixed counters record actual entries/fields and all native solve attempts, including failures. Full simulated-application, full-row reference and exact rational oracles run only in tests.
