# Fixed-base graph-local KLU FTRAN — results and decision

The isolated FTRAN spike is numerically qualified on the captured fixed bases and shows a useful repeated-call saving on the four long runtime windows. It is **not admitted to production**: its one-off preparation is expensive, retained exports duplicate native factors, signed zeros differ, and neither complete update-chain integration nor whole-solver speed was measured. The next useful step is bounded source attribution/removal of setup cost before considering integration, not a dynamic SCC/update project or an automatic rollout.

## Setup, allocations and retained memory

Warm factor+context preparation was measured separately once per arm/case, with zero compilation; this single setup observation is not a paired setup benchmark. Candidate runtime preparation26.1–29.9ms versus native9.3–16.9ms; extra9.2–18.4ms. Aggregate allocation traffic20.2–21.6MB and approximately571–577thousand events versus native2.47–2.62MB/18events. These counters can include native allocations via Julia callbacks; their precise allocation-site attribution is **not captured**. Do not assign them to a particular loop or allocator without evidence.

Measured native batches allocate112B/2events, eligible candidate208B/4events. Both numbers are invariant across batches of8 and640 calls in these data: the observed extra96B/2events is per batch, not evidence of96B per solve, and there is no allocation-growth signal per repeated solve. The batch explicitly creates a7-element route counter vector and returns scalar statistics. This is whole-call+batch accounting, not a separate isolated zero-allocation solve measurement. All cold checks/digests/directed bounds/GC/setup occur outside those windows.

Runtime candidate private export+scratch primitive payload6.03–7.37MB versus reference RHS0.228MB, extra **5.53–6.81MiB**. Julia-reachable wrapper graph grows from2.47–2.62MB to8.27–9.76MB (includes headers/native input CSC owners). Native reported retained size is unchanged per pair,6.44–7.80MB, additional to Julia graph and excluding unspecified hidden/native allocator or OS retention effects. The native factor is intentionally retained for BTRAN/fallback; exports cannot be advertised as free. One-process peak RSS644592KiB covers compilation, captures and checks too; it is not per-context native memory or a free-balance proof.

A rough arithmetic amortization of the single observed extra setup time against each case's median per-call saving gives about211–699 FTRANs per fixed base, about286–655 for the four long windows. This is a conditional estimate, not a measured public-solver break-even: reuse frequency, actual refactorization, non-entering RHS, BTRAN/update histories and mixed-call caches were not exercised. At80 solves the additional setup cost would exceed the observed repeated-call saving. Therefore the current implementation does **not** establish a net speedup for the demonstrated80-column lifecycle.

## Numerical and ownership evidence

Every cold query/cycle/arm passed original-B finite scaled residual <=min(1e-10,128*n*eps64). Maximum across all controls/cases1.6654e-16; runtime maxima<=3.513e-18. Local/native maximum relative difference1.1111e-11 (limit1e-6). First query of each case/arm has a separate256-bit directed residual enclosure:36 bounds pass; this is a diagnostic oracle, not increased production precision. Both cold cycles and before/after A/B/export hashes passed. No public certificate or complete hidden trajectory was tested.

Local vs full exported results match nonzero bits; both-zero values are allowed by this spike's oracle. Runtime signed-zero mismatches are numerous (approximately2.69–2.87million over the160 long-window comparisons per case), and are explicitly counted. They come within an omission experiment; this is **not** signed-zero or general scalar-observability equivalence. This limitation alone prevents automatic production replacement under a stronger original contract. Small bypass arms have identical local/native results; this does not expand optimized precision/backend scope.

Cold microtests cover dependency order, partial budget fallback, epoch rollover, private and partial unsafe_wrap alias rejection before mutation, source preservation, independent scratch, actual new-factor replacement invalidation, singular replacement preservation, Inf/NaN/-zero and scaling-overflow fallback with later reuse, eligible dense-column fallback, unknown-support fallback/alias rejection and an intentionally perturbed output rejected by the residual oracle. Contexts are single caller, own private arrays/indices; arbitrary external field mutation/concurrent use is excluded. No copy/update lifecycle generality, native rollback/free, or callback ownership proof is inferred.

## Decision and remaining work

Keep the candidate isolated. This experiment found a concrete repeated-call saving on runtime with numerical residual qualification, together with enough setup/memory/observability cost to withhold integration. Investigate preparation allocation sites from source first; a future measured preparation change needs its own specific candidate/review. If net lifecycle saving becomes plausible, qualify normal full-base FTRAN/update-chain lifetime and signed-zero contract explicitly before production work. No threshold tuning, dynamic block maintenance, new LP solve, BTRAN optimization or repeat measurement was performed here. No production/permanent test/environment/CI/master change; HH reuse remains disabled.
