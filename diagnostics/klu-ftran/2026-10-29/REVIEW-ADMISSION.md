## Findings

**Important — initialize the parametric context epoch with UInt32(0).** GraphContext declares epoch::UInt32, while prepare at candidate.jl:46 passes plain Int0 in that slot. The default outer constructor for a parametric struct requires the declared nonparametric field types; do not rely on conversion through an inferred outer dispatch. Use explicit UInt32(0). This constructor concern was identified by the coordinator during review and independently checked against the declaration/call here; no Julia was invoked to test it. The explicit type is a necessary narrow prelaunch correction, not a numerical change.

**Important — remove the redundant O(n) full-control work clear.** candidate.jl:125 calls `fill!(c.work,0.)` before deciding the full/local mode. The full branch at line128 then writes every work slot from the scaled permuted RHS. That extra full-vector store pass is unnecessary and makes the all-block Julia control pay avoidable work, inflating the apparent local/full saving. Put the clear in the local branch; retain local reset/fallback safety. Native/local comparisons do not directly depend on this flaw, but the all-block control should be a credible control. Rebind the amended candidate before launch.

**Minor — F is not sorted by this combined export.** PLAN.md:7 describes sorted CSC L/U/F. The pinned wrapper KLU.jl:269 calls native sort, but its F property implementation explicitly documents that F is not sorted on output (line357). export_once does not sort F. Describe L/U as sorted and F as native extraction order. This does not break correctness or shared arithmetic order: both exported arms traverse the very same F arrays/column order, and assertions validate its block-upper direction.

Coverage caveats, not launch blockers: the small dense and irreducible controls deliberately take NativeOnly, so their timings measure eligibility bypass rather than an eligible GraphContext's dense-producer branch. `dense_ftran!` unknown-support fallback is covered by a cold microtest but not a timed arm. The offline verifier checks the exact set of case names, total489 queries and per-case sample/call consistency; it does not independently replay entering columns or enforce the expected80/80/1 query counts per history. Source inspection establishes those counts. It checks recorded numeric bounds/enclosures, not independently recomputed numerical vectors, which are not serialized. Reports must preserve these limits.

## Numerical, alias and lifetime assessment

The bound relation is `(L*U+F) = diag(Rs)^(-1) * B[P,Q]`. Both arms map original RHS rows through inverse P, divide by Rs in final pivot-row order, solve diagonal blocks from highest ID downward, subtract each solved block's F contribution into earlier blocks, and scatter with Q. Unit L diagonals are skipped, U diagonal divisions retained. Rowpos is invperm(P), not Q. Exported L/U arithmetic within each block is identical in full/local arms. The maxheap ensures a block is processed only after every reachable higher predecessor; strict earlier-target F direction and marks suppress repeated enqueueing without dropping later contributions. No cancellation-based reach pruning or tolerance is introduced. Explicit-zero F slots still incur arithmetic/visit cost but do not add edges. Potential signed-zero differences from omitted zero blocks are expressly counted/tolerated only when both values are zero. Native packed order may differ from sorted exports, so native agreement is residual/relative-bound based rather than bitwise.

Inputs/exports are validated once, private and immutable during calls. Pointer-interval checks reject whole and partial Float64 buffer overlap with source/private destination storage before RHS/work writes. Index arrays cannot alias ordinary Float64 buffers without hostile reinterpret/private mutation, which is outside this private API's scope. Sizes and entering bounds are checked first. The original dense RHS remains intact throughout local work; destination writes occur only after successful local completion or native fallback. Dense-source, reached-weight, nonfinite/negative-zero and active nonfinite arithmetic routes retain the native solve. A new native factor is built before replacement invalidates exports; failure therefore preserves the old context, while successful replacement routes subsequent calls native and cannot read stale exports. Exports intentionally remain retained after invalidation in this bounded context. Factors and scratch are private, arms use the candidate sequentially, and concurrent mutation is explicitly excluded.

Cold Test assertions cover heap reach/budget restart, epoch rollover, alias rejection including partial unsafe_wrap, preservation, separate scratch, singular replacement failure and actual successful invalidation, nonfinite/negative-zero source fallback, scale overflow followed by reuse, unknown dense fallback, bad-output oracle sensitivity and dimensions/bounds. Ordinary Test has a single proper testset. Every actual/control query in two cold cycles checks finite normalized original-B residual for all arms, local/native relative difference, and full/local equal nonzero bits when local completes. The first query of every case has all three 256-bit directed residual enclosures outside timing. Directed accumulation bounds the exact Float64-data residual; the downward-computed denominator/tolerance bound is conservative. This is additional certification precision, not changed solve precision. These are planned assertions, not claimed passes.

## Work, allocations and retained memory

**No unnecessary NEW production work or memory cost was introduced: no production code changed.** The Important finding is unnecessary diagnostic full-control work. Beyond that redundant scan, no material avoidable diagnostic retention was found for this stated experiment. Candidate duplication is real: its native fallback factor and owned extracted L/U/F coexist. The reference has an independent factor/RHS. Each eligible setup copies factor input, factors once, calls one combined sort/extract, allocates owned arrays and scratch/maps, sorts two permutations for validation, scans finite/scaling/triangular/block invariants and totals block weights. These are setup costs, not per-pivot operations. Primitive export/scratch payload and native-reported memory are recorded separately; summarysize does not measure native allocations and summing its wrapper total with primitive payload would double-count Julia storage. Native finalizer/free completion is not proved.

Each local call pays original RHS clear O(n), entering scatter O(nnz column), private work clear O(n), a second source walk for scale/seed O(nnz column), active L/U/F visits, heap operations O(reached blocks log blocks), active finite checks and final dense Q scatter O(n). F discovery is fused with arithmetic; no separate CSR/reach census/full invariant scan is added per call. Native pays RHS clear/scatter, dense destination copy and native solve. The full control gathers/scales all n and visits every block; remove its redundant clear. Fallback pays any sunk local work plus a complete native solve, without reconstructing the original RHS. Epoch rollover clears O(blocks) marks and is a cold test, not an ordinary iteration cost. Update-chain length is absent in this fixed-base experiment; no conclusion about full update-chain or solver cost follows.

`last_blocks`/`last_weight` and their batch sums count **exported arithmetic only**. Native routes show0 for those counters even though they perform a full native solve; reached-budget fallbacks show sunk exported work in addition to uncounted native work. They are not total work/flop counts. Fullweight counts L offdiagonal slots, all U slots/divisions and F slots, with different operation costs. All arms include source preparation, guards and the same scalar checksum/route observation. One seven-element path vector allocation per batch is common. No full result hash/residual/certificate scan is inside measurement windows. Five measured rounds rotate arm order but do not fully balance it; paired/min/max distributions and GC/allocation events must be reported, without inferring savings from iteration counts or one timing.

Actual scheduling is9 fixed bases (each of3 histories at0/80/160) with80/80/1 actual next entering columns:483 queries/cycle. Coupled-forced256 adds3, dense-native-only256 adds1, irreducible-native-only256 adds2. Two cold cycles over3 arms yield2934 whole calls;2 warm rounds *8 repeats *3 arms yield23472;5 measured rounds yield58680. Tiny microtests and setup calls are additional and outside these counts. Within each history, anchor80 applies steps1:80 and anchor160 applies81:160; query index is state+1, so fixed bases receive the subsequent actual entering columns.
