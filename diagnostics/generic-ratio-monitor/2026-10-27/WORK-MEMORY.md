# Computational work and memory

A runs inside both original primal ratio passes and the existing relaxed-limit update. A strict-positive integer comparison avoids constructing an unused BigFloat zero; zero/negative/nonfinite fallback retains the original fresh zero and max selection. Each reached clamp adds a cheap predicate; at most O(m) temporary zeros are removed, with the same row/rejected-candidate traversal, pivot/tie decisions, division order, feasibility/snap checks, and returns. The zero fallback is not a shared mutable constant. Negative/tolerated/exception paths have correctness coverage; their timing is not inferred from positive-step measured fixtures.

B runs at each monitor observation, once for primal step and conditionally for dual step. The same BigFloat sign is tested and negative operand is rounded by the same unary negation. Nonnegative inputs omit its discarded eager negation. Other types still call abs through the generic helper. No reordered division, shortcircuit, conversion, tolerance or state mutation. At most two unused negations are removed per observation; negative-only inputs can save none. Whole workspace observation retains the full finite/context/hash/metric scans, precision selection, possible monitor rebuild/rebase, event and callback boundaries.

C runs at each of the three end-window improvement evaluations, after the original equality gate. Its BigFloat-only method retains both normalized divisions, subtraction, zero-change branch, final multiplication, max argument ordering and fresh zero returns. At most two unused nonnegative negations per reached metric are removed. All other scalar types retain the original improvement method. Mixed stored precision is qualified both directly and through the original recovery-precision wrapper.

All variants add O(1) transient scalar/helper state and cold compiled method metadata only. No new full vector/matrix scan, basis solve, array copy, conversion pass, invariant pass, persistent cache, shared mutable arithmetic constant or update-chain-dependent storage is introduced. Input/scalar/array identity preservation, result alias topology, full monitor fields, exception partial state and global precision/rounding restoration are checked outside timing. Fixture/reset/warm/cold/validation/GC preparation costs are separate; all measured GC windows and timing outliers remain. Lower allocation traffic does not prove lower live/native retained memory, universal solver speedup or observer neutrality. Independent review must state whether unnecessary work or memory was found, against actual admitted/tested production bytes.
