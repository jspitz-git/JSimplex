## Variability and limits

No universal speedup is claimed. Cell median timing ranges include 0.8566–1.2119 for A metric, 0.8685–1.0365 for A primal observation, 0.8666–1.0337 for A dual observation, 0.8920–1.0603 for B initializer, 0.6878–1.0052 for C initializer and 0.6277–1.1973 for B+C initializer. The slowest A metric cell has paired median 1.2119 and within-cell MAD 0.2713; the slowest B+C cell has median 1.1973 and MAD 0.2553. These remain included, not explained away or rerun. Very short unchanged controls show ratios such as 0.5–2.0 at roughly 0.1–0.2 us; timer granularity and the observed dispersion limit interpretation. The strong evidence is the scoped arithmetic/allocation-event removal plus supportive complete-call paired timings across sparse and dense cases, not fewer simplex iterations.

One A primal-observation pair (BF64/Down, dense, n128/m8, unbounded) reports 7856 more bytes despite exactly 96 fewer events. Its cell median still saves 2672 bytes and has paired median ratio 0.9904. Unchanged rational controls also vary in bytes while allocation-event counts stay equal; e.g. Rational{BigInt} C cell-median savings range from -128 to +592 bytes, and B slack-only initializer savings range from -448 to 0 bytes. The cause of these byte variations is unknown. No inference of allocator provenance, native retention, or guaranteed per-call byte reduction is made. Allocation-event counts and byte counts are reported separately.

## Work, memory and setup accounting

No unnecessary added production computational work or memory cost was found. A removes m+u zero constructions per metric (m basic entries and u nonfinite-bound fallbacks) and discarded nonnegative free-price negations; it retains exactly the existing O(n+m) metric work and full finite/context scans. It keeps one already-created zero alive for the remainder of a call, an O(precision) local lifetime extension, with no persistent owner/cache. B keeps the O(m) unit-gate traversal and structural/early-exit ordering, replacing multiprecision temporary arithmetic with bounded comparisons while preserving negative BF rounding. C keeps O(nnz(A)+n) column norms and O(m) slack stores, reducing m row-cacheability checks to one for m>0 and zero for m=0, with O(1) Boolean state and per-row readiness control. None adds solves, vector/matrix scans, copies, numeric conversions, update-chain dependence, or persistent numeric storage. Added method/code footprint is not quantified by per-call allocation measurements.
