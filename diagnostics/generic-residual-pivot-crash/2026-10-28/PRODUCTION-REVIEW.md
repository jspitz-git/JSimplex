## Work, allocation and retained memory

No unnecessary added numerical scans, solves, array copies, conversions, repeated invariant checks, persistent caches or growing retained-memory structures were found. A operates at legacy BTRAN residual certification during pivots and recovery checks; it removes one zero construction per nonleaving row while retaining O(m + basis nonzeros) work. For a valid leaving row this is m−1 removed constructors. B adds up to two O(1) predicates per BigFloat pivot comparison and avoids stored-precision context/abs only on finite positive inputs; the complete PFI count/packing/inverse/division work and update-chain storage are unchanged. It introduces no update-chain-length-dependent work. C is optional crash initialization per candidate column: existing O(m) maximum/eligibility work and O(mk) bounded ranking remain, with one left abs removed per actual ranking comparison. It adds no scan, magnitudes array or cache. One seed/magnitude local may stay live through its current call/row, but no numerical object is retained after that call because of these changes. Additional method/closure specialization metadata is a cold cost, not a proved retention saving.
