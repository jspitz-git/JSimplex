## Findings

- **MAT-R1 (P2), implementation plan lines 55–57:** the prospective old-guard whole-call RED has no scheduled old-candidate arm. The interfaces at line 49 and cost schedule at line 57 specify only reference versus new candidate. The stated 1,920 backend calls are exactly 12 cases × 2 processes × 10 pairs × 2 sides × 4 calls; none remain for reference versus old candidate. The micro equality comparison does not execute the old whole candidate. Explicitly bind/isolate the old candidate, enumerate its process/case/warm/measured schedule, define its expected allocation failure, and include its cost calls in the total within the existing ceiling. Do not hide measured RED calls among setup calls.
- **MAT-R2 (P2), implementation plan line 58:** time acceptance is underspecified. “Pooled time median<1” needs a dimensionless ratio and explicit reducer; side-median ratios and median paired ratios can disagree. Define per-case per-process side medians of per-call times, the pooled reducer across processes, the reference denominator for relative increases, the absolute threshold in seconds, and require every case independently. State the process requirement for absent/equal byte/event savings as well. This prevents a later driver from selecting among non-equivalent acceptance formulas.

## Source/design assessment

Installed mpfr.jl:112–114 constructs the global Ref and a no-default rounding ScopedValue; mpfr.jl:247–256 uses scoped lookup followed by the global fallback. Installed scopedvalues.jl:203–218 asserts the current Scope union, returns nothing for absent no-default keys, and type-checks the present value before wrapping it. Therefore the proposed helper's absent-key true branch and present-key typed equality preserve the original predicate when global writes are serialized. Explicit scoped modes equal to global must remain eligible. An absent rounding key inside a nonempty precision/unrelated scope is correctly distinguished from no task scope. No support for forged private storage is claimed.

Installed dict.jl:997–1009 delegates hashing/traversal to the existing HAMT, returning nothing or a one-element Any-valued tuple. Installed hamt.jl:87–116 and 158–186 retain identity matching and read-only copy=false traversal. Installed expr.jl:347–381 documents call-site precedence over definition annotations and the limit that inlining can fail. The source-level Bool helper removes the Some return boundary and exposes the tuple; this does not prove zero emitted allocations. The plan appropriately forbids direct HAMT clones, caches, effect assertions and broad solve inlining, and makes runtime zero allocation a later gate.

MA-R/candidate.jl:4–9 checks exact vector/backend storage and shape/n16 before rounding; lines 14–25 delegate before scratch/mutation on rejection. The future byte-exact inverse at plan line 40 is an appropriate guard against unrelated arithmetic changes. Nesting, inherited tasks, yields, exceptions, consecutive serialized global changes, aliasing, retained leaves and partial-write exceptions have explicit future tests. Unsynchronized concurrent global rounding/precision writes remain outside the original contract. Source-hash admission before prototype load addresses the pinned runtime; production runtime support remains a separate obligation.
