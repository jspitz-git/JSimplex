The source supports the mechanism: split-upper.jl:386 importer validates column pointers and computes K before allocating; :414 stable-column traversal currently assigns CSC offsets to starts and tight capacities. :278 insertion reserves rows independently and reserves a coefficient block only when count reaches capacity (or 32). All five review focuses are adequate planning requirements:

1. Nonidentity q: physical order follows stable column IDs, which can differ from CSC order. A capacity-based physical cursor and separate source cursor are necessary. The planned adjacent short tails, 33/34/35/36/64 boundaries and exact partition oracle target wrong starts, overlap and skipped source tuples. Initial descriptor count stays K0, empty columns create no extent. Arithmetic gives capacities [32,2], [32,4], [32,4], [32,4], [32,32].
2. Explicit/signed zeros: raw CSC live entries must remain live with their original bits; only added slack is +0 with zero IDs/backrefs. Import tests must inspect live bits and slack separately. Existing exact-zero mutation behavior is preserved. A materialized numeric equality alone would be insufficient; the plan explicitly requires bitwise and structural oracles.
3. Bounds/failure/ownership: each tail adds at most two slots, every capacity is at most 32, so C0=m+Delta<=32*K0 and Delta<=2*n. A test in which only padded C exceeds a limit while 32*K0 fits is impossible. Planned zero-allocation limit rejection, malformed CSC/q order, each-buffer injected failure, checked physical endpoints, disjoint padded copy and old-factor publication cover the relevant risks. split-bg.jl:459 constructs a complete candidate before field publication; split-upper.jl:443 copies complete coefficient capacities. Failed updates retain existing partial-edit semantics, not a new transactional guarantee.
4. Handles/caches/mutation: reserved insertion must separately count row work. Merge, free reuse, full32 split, row rotations and copy divergence are required because larger extents alter storage trajectories. split-bg.jl:136 invalidates prepared state before mutation; :410 begins the update before edits. The entering FTRAN / distinct DSE / replacement test protects the existing two-entry prepared cache contract across relocation and refactor. No new mutable metadata or alias relaxation is proposed.
