## Exact arithmetic-policy boundary

Allowed: different order across independent trailing columns, explicit `fma(-multiplier, source, target)` in admitted dense panel updates, bulk final packed writeback. No `@fastmath`, reassociation across dependent pivots, approximate reciprocals, threshold dropping, precision increase or changed factorization controls. Scalar fallback retains the original arithmetic.

At pivot k, use the CURRENT candidate tile entries a=U[k,k], b=U[k+1,k]; swap iff `_pivot_magnitude(b)>_pivot_magnitude(a)`, retaining strict-tie behavior, then check the selected pivot for zero and form the original division. The input pivot-row/tolerance validation and prepared-spike selection remain original. Same policy does NOT mean identical pivot choices to the reference: rounding can change a near tie. Record and validate each side's decisions against its own predecision values; exact equality is required only for fixtures expressly constructed with exact, separated pivots.

Never drop a small finite coefficient. An exact computed zero uses existing packed zero-deletion semantics. Missing entries read as +0; stored signed zeros and their behavior require separate presence/touched masks, not a dense value-only inference. Ineligible explicit-zero/NaN/Inf input bands take scalar fallback. Underflow, overflow and cancellation in admitted arithmetic remain tested, not suppressed.

## Panel algorithm and dependency barriers

Keep original `_prepare_spike!`, `_begin_upper_update!`, initial incidence preparation/replacement and column rotation. Clone only the BG update route in an isolated namespace; no global production method overwrite. At the start of a panel with next elimination r:

- Set b=min(8,n-r), h=b+1, w=n-r+1. Eligibility requires64<=n<=4096, b>=4, w>=64, at least half of the h*w logical band entries structurally present, and all gathered stored band values finite/nonzero. Counts use current packed entries, including below-diagonal spike entries. No whole-matrix density scan.
- Gather rows r:r+b and columns r:n into private storage X[column_offset,row_offset]; contiguous Julia columns thus represent logical rows across trailing columns. Use logical indices through UpperRowOrder; do not treat physical IDs as row numbers. Gather original presence separately and start touched masks empty. One sparse interval lookup/traversal per affected packed column, with explicit work counters.
- First ineligible panel in an update ends blocking for the rest of that update. If n/width/step bounds fail, do not allocate or scan. No repeated density trials through a sparse suffix.
- Work entirely in private X while processing k=r:r+b-1 in chronological order. Before each step, if the current diagonal is exactly zero, reject the ENTIRE uncommitted panel and execute the original scalar suffix from r, so `_last_pure_bartels_golub_swap` sees the complete packed state and may cross the panel boundary. Do not approximate or truncate the pure-swap lookahead. A nonzero current diagonal makes that original lookahead return immediately, which justifies omitting it in the admitted panel.
- Otherwise perform the strict adjacent pivot comparison, swap the two logical tile rows when required, and eliminate. The pivot-column subdiagonal is explicitly set to zero. For each later column, reproduce the original structural-source visitation: perform the FMA only when its current source entry is present; a zero multiplier skips all trailing arithmetic. Track presence changes and exact-zero deletion after each operation, preserving untouched stored zeros if any arise through swaps. This avoids inventing arithmetic on absent coefficients.
- Every intermediate newly computed coefficient is checked for finiteness; invalid intermediates must conservatively clear upper-prefix eligibility even if the final value would be finite. Reject the private panel on any nonfinite coefficient or invalid pivot/multiplier, then use the original scalar suffix from r with that conservative flag retained. At most one rejected panel per update, at most8 attempted steps repeated. This explicit bounded algorithmic fallback is counted and distinct from an extra solver/refactor attempt. No catch-all exception-to-fallback: allocation errors and unexpected exceptions propagate.
- Record at most8 original-format BartelsGolubStep operations in private scratch. Swaps are individual adjacent steps; successful admitted panels have no pure-run compression. Their representation must produce the same mathematical history action as that sequence. Original scalar suffix preserves its run compression.
- After a successful panel, bulk merge each packed column's affected logical row interval once. Keep shared UpperRowOrder unchanged during panel processing: map each final logical row back through order.order, rather than also applying the original global row permutation. Earlier columns have no nonzero entries in this band; verify this invariant in structural tests. Preserve all coefficient/index entries outside the band and all input/prepared-buffer ownership.
- Rebuild ONLY the h affected incidence rows by visiting stable column IDs in ascending order and mapping them via factor.positions. No sort and no full incidence rebuild per panel. Other rows are unchanged. Reserve necessary column/row capacities before destructive writeback where practical, account for all growth, and invalidate caches before mutation. Do not claim whole-update rollback on allocation failure. On any partial failure, no finish/publication of cache eligibility; caller recovery/refactor behavior remains authoritative.
- Append panel history once after successful coefficient/incidence writeback; advance r by b. Before scalar suffix or return, no deferred numerical operation remains. Append exactly one update record for the entire replacement, then invoke original `_finish_upper_update!` only on complete success. Preserve prepared two-RHS provenance and all original cache invalidation.

The tile does not delay pivot data: every panel column is updated during every preceding step. No solve, checkpoint, observer or next update can see uncommitted tile values. No second full factor or full U snapshot is introduced.
