## Manual numerical and design conclusions

The new full qualification is justified by a changed candidate: the MA-U helper
repairs the guard after the old MA-R full component rejection, and accepted MA-V
provides scoped local guard evidence. MA-W completes the original obligations for
this changed candidate; it does not rerun the unchanged rejected MA-R route.
Rational returns at the first BigFloat type check, so the helper change supplies
no causal explanation or prediction that Rational bytes improve. Its historical
both-sign byte differences and equal event counts remain unresolved. A new PASS
would describe this fixed experiment only. A failure consumes the attempt; the
plan correctly prohibits tuning, repeated favorable-history attempts and immediate
allocator investigation under this allowance.

Original MA-S-2 aggregate source and original MA-Q rules match the plan: targets
use matched paired time ratios, per-process ratio median<1 and strictly smaller
side-median bytes/events, then pooled ratio median<=0.95 with at least15/21 wins.
Controls use differences of side medians with10%/0.4us per-process and5%/0.2us
pooled time allowances, and no byte/event increase in each process. Both Rational
directions remain mandatory. Neither MA-V's target ratio-of-side-medians rule nor
paired byte differences replace the original reducer. All samples, GC and outliers
remain, and measured compile/recompile must equal zero. Per-process strict cost
validation is a deliberate stronger continuation gate: a rejected process cannot
be followed by another process to rescue acceptance through pooling.

The original reference/tests/fixtures remain frozen. MA-U instrumented entries use
the same current eligibility helper and unchanged arithmetic helpers, so explicit
path pinning and inverse checks can bridge original160-case tests to this candidate
without restoring the old guard. The planned exact source identity checks are
required before reusing accepted MA-V scope/transition/owner evidence. The plan
honestly retains source-only coverage of actual no-scope behavior. Exceptions,
partial destination, leaf ownership, precision, signed/nonfinite tokens, fallback
before writes, tolerances and arithmetic order remain protected.

MA-S-LOAD's outer invokelatest boundaries cover correctness and costs after include,
outside timers; process1's missing-route RED must precede candidate load and mean
exactly two Test.Fail records, never loader failure. MA-X must concretely implement
and independently test those boundaries, exact loaded-source paths, explicit
fail-closed Python checks, strict per-process gates, and partial-record schemas.
The plan sufficiently assigns these obligations and requires saved metrics before
conversion/checks, enriched records before assertions, flushed journals and logs
for pre-raw failures. It makes no power-loss guarantee. Synthetic refusal/truncation
and terminal tests use fake processes/files, not an unsealed Julia run.

MA-Y remains separately sealed: one sequence, at most three90s inclusive processes
and270s cumulative; copied/adapted supervisor retains TERM84/KILL88/wait90, exact
identity checks and cleanup failure rejection. Unsupported runtime/source refuses
before loading private APIs. Compatibility, direct dependency and clean loading,
PFI lifecycle, public afiro/sc50a measurements and any production integration stay
separate conditional original Task3 obligations.

## Computational work and memory review

No unnecessary production work, allocation or retained memory was found: this
step changes documentation/evidence only. No production benchmark is warranted.
The candidate itself retains one current-scope lookup per otherwise eligible-size
call, no new matrix/vector scan, solve, conversion or cache; dictionary traversal
scales with scope storage, while unchanged solve arithmetic/scans scale with n and
precision, not update-chain length. Rational does not reach that lookup.

Independent fixture/source accounting confirms488 direct smoke/correctness entries,
162 correctness/smoke setup factorizations including2PFI constructors and2PFI copies;
156 cost setups give318 total. The complete ceiling is12,480 cost entries and3,120
windows (936 warm/2,184 measured),12,968 direct entries combined. Nested fallback
reference calls, factorization internals, imports and runtime work are additional;
these are source budgets, not observed allocation counts or full PREforward counts.

The full original matrix is necessary for candidate qualification. Reusing MA-V
coverage avoids another840-case suite, microbenchmarks, old allocation REDs, hooks,
A/A repeats or new LLVM probes. Correctness repeats only in process1. A failed
process stops later processes. Thus no unnecessary proposed new diagnostic work
was identified within this selected strict qualification question. Diagnostic
independent bundles, O(n²) snapshots/owner checks, tokens and append-only journals
outside timing retain memory and can affect later GC/cache behavior; the plan
acknowledges this and requires exact records rather than neutrality claims. MA-X
must freeze their concrete schema/counts before execution. Dense and zero-heavy
fixtures exercise the native dense backend; zero-heavy does not imply sparse CSC
or public-solver coverage. Cold load/setup observations cannot establish pure
compilation cost, and future local savings cannot establish live memory reduction
or end-to-end solver speedup.
