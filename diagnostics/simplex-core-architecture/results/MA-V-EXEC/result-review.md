## Manual numerical and source conclusions

These are reviewer judgments based on the accepted design, unchanged source,
recorded assertions and recomputed checks; they are not mechanical PASS flags.

The only candidate change is the local Bool helper and one eligibility call.
The exact inverse recovers MA-R byte-for-byte, preserving all 12 MA product sites,
arithmetic order, tolerances, precision behavior, eligibility thresholds, aliases,
and exception/delegation order. With no scope or missing rounding key, the helper
returns true, matching equality against the same global mode. With a present key,
it uses the installed persistent lookup, asserts the supported enum type and
compares that value with the global mode. No cached scope survives calls or yields.
The private API/runtime dependence is explicitly pinned and unsupported runtime
is refused before candidate loading.

The recorded test source compares exact finite rational tokens, sign and stored
precision; NaN/Inf classes; factors, pivots, RHS and old mutable leaves/identities;
retained outputs; and exception type/message plus post-exception destination.
The uninstrumented, original and separately instrumented arms are compared before
reported route counts are accepted. Fallbacks occur before scratch or mutation.
RHS views, same-container and shared-leaf aliases, copied PFI ownership, singular
and invalid pivots, wrong lengths and mixed stored/ambient precisions are covered.
Mode/precision restoration is asserted in finally blocks, including nested throws
and serial inherited tasks with yields; both final ambient-restored fields pass.

Actual no-scope availability is FALSE with zero no-scope records. The no-scope
branch has source reasoning only. Missing-key active scopes, including unrelated
keys and precision scopes, do have runtime coverage. No dedicated no-scope runtime
pass is claimed. Numerical equivalence is supported within the admitted finite
fixtures and precision/mode coverage, not proved for arbitrary future runtimes.

The generated batch code supports repeated probe execution without invariant
collapse. The 749-byte new probe delegates to _dense_ma_rounding_matches, so it
is not a measurement or bound of the transitive helper body or native code size.
Micro timings include the fixed noinline boundary; whole-call gates remain the
acceptance measure. No new compiler experiment is required or authorized here.

## Work, allocation and memory review

No unnecessary increase in computational work, allocation or retained production
memory was found. Production is unchanged; the local candidate guard adds no
full-vector/matrix scan, basis solve, copy, conversion, persistent cache or retained
task/scope. Type/storage/shape/n16 tests short-circuit first; otherwise there is one
scope read and at most one existing persistent-map lookup per backend call. Its
work depends on scope-map lookup depth, not matrix dimension/nonzeros or update
chain length. This applies per ordinary, recovery or final-certification backend
entry if a future separately qualified integration calls it there; no solver-level
frequency was measured in this experiment.

The existing O(n^2) dense triangular arithmetic and one privately owned BigFloat
product scratch per eligible call are unchanged. Mismatch/n15 calls delegate
without scratch. All supported tested precisions 128/256/512 and mixed precision
fixtures preserve exact semantics. No safeguard was removed for performance.

Focused measurements support this local decision: the guard's six contexts in
each process have zero measured candidate bytes/events, and all eight whole-call
mismatch/n15 controls have equal candidate/reference byte and event medians in
both processes and pass the fixed time budgets. The four eligible n32 cases have
strictly lower bytes/events and pooled candidate/reference time ratios about
0.6170–0.6857, with each process also below one. These whole-call savings include
the existing MA arithmetic; they do not isolate the incremental guard time.
No statistical significance or end-to-end speedup is inferred from two processes.
Dense and zero-heavy dense fixtures were measured; sparse CSC backends were not.

Call accounting explicitly excludes hidden/native/import internals. Source-derived
nested delegations add 1,120 correctness reference entries and 720 cost reference
entries to the named direct counts. The 866 diagnostic bundles, snapshots, resets,
tokens, records and journals are outside timed windows but consume resources and
may influence later GC. Three measured GC windows are retained among 532 measured
cost/micro windows. Baseline allocations are not subtracted. Reported counters
are aggregate allocation traffic, not retained-memory/object-graph proof.

Load, setup, compilation, correctness, code inspection and inclusive diagnostic
intervals are separated in the qualification report and raw evidence. The two
supervised intervals are 26.838440328/9.809628626 seconds, below the admitted caps;
these inclusive execution times are not kernel benchmarks. No full solver,
recovery workload or final-certification workload was benchmarked.
