## Numerical and ownership assessment

Installed MA 1.8.1 implements buffer_for(add_mul, BigFloat, BigFloat, BigFloat) with one BigFloat product buffer, followed by separate mpfr_mul and mpfr_add. It does not substitute FMA or reassociate the dot. Julia 1.13 BigFloat owns mutable Memory in field :d, matching the identity checks. Scratch is constructed within each precision scope, checked at 128/256/512 bits and reset each dot. Scoped RoundNearest and precision restoration are checked. The fixture integer numerators require at most 85 bits, so Julia's rational conversion via separately converted numerator/denominator followed by division agrees with the oracle's correctly rounded rational inputs at every tested precision.

For Rational{BigInt}, MA resets numerator/denominator, cross-cancels products and reduces sums using private BigInt buffers. The scratch has 12 mutable leaves: accumulator 2, product scratch 5, product 2, sum scratch 3. Distinct leaf identities are checked pairwise and against input leaves; identities and unchanged input values are checked after every window. Buffers do not escape into solver state. The Ref output intentionally borrows the accumulator and changes on the next candidate call; no independent retained result is promised or measured.

Each window must reproduce the plain sequential result; all outputs are also checked against an independent exact rational model of the actual rounded inputs. Python audit recomputes round-to-nearest/even multiplication and addition at every step, exact dots, and gamma(2n)*sumabs with u=2^-bits. These finite, modest-exponent fixtures cannot encounter overflow/underflow. Rational results require exact equality. No tolerance, coefficient dropping or precision inflation is introduced.

Fresh reviewer Python tests used a separately written normalize-and-nearest-integer rounding algorithm, with 12,312 small signed rational comparisons, all 12 complete fixture/sequential/error-bound cases and 16 schema/predicate mutations that must be rejected. All passed. This establishes offline oracle consistency, not Julia syntax/runtime execution success; a runtime failure must remain a failed attempt with preserved evidence.
