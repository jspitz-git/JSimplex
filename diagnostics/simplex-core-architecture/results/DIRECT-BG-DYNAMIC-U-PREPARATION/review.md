## Algorithms, ownership and test oracles

Construction validates square CSC structure and a dimension-matching permutation, then visits stable original basis IDs ascending via inverse q. This gives row order by stable column ID and column order by logical row; q=[3,1,2] specifically distinguishes those contracts. Each coefficient has one owned slot value. Input arrays/q are copied into independently owned arena state; signed explicit zeros, Inf and NaN payloads are copied without arithmetic. Known-slot stores delete both exact zero signs and retain finite nonzero/subnormal/nonfinite values. No tolerance or precision change is introduced.

Link checks supplied row/column neighbors in constant work and reserves before modifying either index. Free slots are reused; unlink clears metadata and returns the ID to the free list. Checked capacity arithmetic and private construction of all seven replacement vectors keep the old state intact on allocation failure under the documented fresh-independent-vector allocator contract. The allocator is call-local and not retained. Internal IDs remain confined to primitives/tests; no external handle cache exists.

Adjacent-row swap merges stable row lists. When both rows share a column, their old logical adjacency guarantees adjacent column nodes, which are exchanged before row maps change. A sole occurrence remains correctly ordered. Rotation traverses each moving-row column interval under the old map, detaches/reinserts only that node, then rotates maps. Coefficients and physical IDs remain unchanged. The selected-state/permutation oracle works from original CSC bit tokens and independent row permutation, while the test-only checker enforces reciprocal links, strict ordering, uniqueness, inverse maps, distinct ownership and exhaustive disjoint free/live partition. Coverage includes empty, identity, nonidentity q, signed zero, absent entries, fill/deletion boundaries, repeated reuse, growth/overflow, seven failure points, dirty successful allocation, swaps/rotations/inverses and corruption cases. No executable numerical qualification follows from source inspection.
