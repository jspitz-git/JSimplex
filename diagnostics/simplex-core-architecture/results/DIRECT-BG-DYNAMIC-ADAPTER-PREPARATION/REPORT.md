## Numerical and ownership contract

`DynamicBGFactor{F}` is a separate eight-field type, not an AbstractTriangularBasisFactorization subtype. Its factory admits only native threshold_one and Markowitz default before factorization. It calls the existing factorization/export/normalization once and constructs slots directly from exported CSC/q. It never constructs a temporary packed BG. Real exporter fallback retains the ordinary backend and an identity arena. Unsafe normalization retains the unchanged unnormalized export. The existing DirectLowerBackend solve/copy implementation is reused exactly.

Dense Vector{Float64} FTRAN, BTRAN, unit-BTRAN metadata and replacement are the only supported solve/update routes. Unsupported buffers, precisions and keyword modes are rejected before backend access. The test-only RejectBackend makes even an unintended dimension query fail. No old union, method, production factory or policy is modified.

FTRAN preserves lower solve, composed history order, independent upper/history coordinate maps, two prepared slots, buffer identity plus isequal provenance, finite publication and eviction even for ordinary auxiliary solves. BTRAN preserves ordered subtraction/division, unit-prefix eligibility, reverse composed operations and scratch alias handling. Exact-zero omission, pivot magnitude, tolerance conversion/check order, pure-swap batching and history publication after successful completion follow the reference. No tolerance/precision changes or small-coefficient dropping.

Column links are ordered by logical row; row links by original basis-column ID. Elimination visits source IDs in the same order as the original incidence list, with one monotone target cursor. Source/next IDs are captured before target deletion/insertion. Row permutations change maps and affected column links. Copy duplicates all15 arena vectors and scratch, shares immutable active update records and read-only lower arrays as before, starts a fresh cache, and never recycles a shared prefix. Dynamic copy preserves physical IDs; packed copy rebases them. Tests compare logical state and deliberately rebase a separate test-owned copied arena to force different history/upper maps. That extra arena construction is test-only and must be counted in Task3 preparation.

Refactor builds a complete replacement with unchanged backend/policy/normalization intent, checks the concrete type, then publishes. Failure before publication must preserve the old factor. A failed update is a partially mutated/ineligible state with no successful history record; tests do not solve that state. Neither operation proves native backend rollback or full graph reclamation.

## Computational work and retained memory

All counts here are source-derived, not measured allocations or speedups.

- Setup/refactor: the same real backend/export/normalization work plus O(n+nnzU) arena validation/import. q positions and arena maps are owned. Fallback temporarily constructs an identity CSC before arena import. There is no temporary packed factor or retained second coefficient representation. Full refactor still rebuilds, with old/new objects coexisting until publication.
- Each solve: existing lower work, incremental history compilation (O(new steps), retained operations O(history)), full ordered arithmetic over active upper columns, O(n) coordinate handoffs, and existing prepared-slot payload/provenance scans/copies. Dirty active-column rebuild examines only the invalidated suffix. No full arena invariant/finite check or materialized sparse matrix is called on the hot path.
- Each update: prepared lookup can compare up to two n-vectors; a miss reconstructs over live upper coefficients in reference order. Column replacement scans n spike values, unlinks old entries and finds stable-ID row gaps for new entries. These row-gap searches can cost the sum of visited row prefixes; no universal linear bound is claimed. Exact spike clearing remains one n-pass to match reference private scratch. Row elimination merges the source row and target prefix, mutating shared slots in place; growth only when needed. Pure-swap row rotation traverses affected column intervals and updates the row map.
- R1 removed the concrete repeated head-of-row quadratic lookup pattern. The saved integer access witness covers n8/16/32/64. Common Hessenberg pivot entries lie at the column tail or predecessor. A potentially continuing pure chain scans the carried row once, then lower-tail predicates; a chain that stops at the next column can still pay that row scan. General non-Hessenberg test states can require longer column walks. Linked traversal/local guards/branches may offset savings; only later whole-lifecycle measurements can decide.
- Arena payload remains56*C+64*n bytes at Int64/Float64, excluding headers. Factor work/spike add16*n; cache order/active storage, composed triples, prepared buffers (up to four n-element arrays plus two caller output references), lower/fallback storage and histories are additional. Growth temporarily holds old/new seven coefficient/link buffers. Copy intentionally duplicates full capacity (including free slots), maps and scratch while retaining immutable shared history/lower arrays; retained high-water capacity can exceed packed storage. No native allocation/free or GC-root reclamation proof.
- All exact rational residuals, materializations, bit tokens, traces, ownership snapshots and the extra map-rebase arena belong to tests outside any future cost window. They do not belong in the production-like candidate or prove observer neutrality.

The initial avoidable repeated row scans are corrected.
