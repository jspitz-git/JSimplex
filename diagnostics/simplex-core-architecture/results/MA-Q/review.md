## Five review classes

1. **Rounding and precision.** Installed Base `mpfr.jl:154-171,247-250,575-582` constructs an ambient-precision result and passes scoped `rounding_raw(BigFloat)` to multiplication. Installed MA `BigFloat.jl:137-148` writes the supplied output and passes global `ROUNDING_MODE[]`. The proposed O(1) equality gate is essential and correctly precedes copy/permutation/writes. A fresh ambient product preserves result precision even when operands have different stored precision. Task2 requires global directed modes, nested mismatches, restored state and exact tokens. These are future verification obligations, not existing proof of all nonfinite/rounding cases.

2. **Shared leaves and retained outputs.** `src/factorization.jl:407-426` shares DenseLU backends between copied factors. Container ownership cannot justify mutating factor or RHS scalar storage. The design mutates only one fresh, unpublished product; Base subtraction/division (`mpfr.jl:618-625`) continue to construct fresh results before array assignment. This is a sound ownership boundary without scalar-ownership scans or persistent caches. Task2 explicitly includes shared scalar leaves, copied PFI backends, destination/RHS aliasing and prior retained outputs. Existing container alias behavior must remain unchanged.

3. **Actual triangular routing.** Installed `triangular.jl:1251-1266` performs `istriu` selection and wrapper normalization before dispatch. `istriu(UnitLowerTriangular(...))` inspects its parent (`435-436`), so upper/diagonal storage can normalize to `UpperTriangular(UnitLowerTriangular(...))`; its outer nonunit treatment and inner virtual unit/zero entries must remain. Transpose construction (`537-540`), orientation/unit metadata (`1158-1170`) and `adjtrans.jl:87-89,326-333` determine the other normalized paths. The eight generic source branches (`1635-1769`) include initial unit division and different accumulation/store orders. A fixed four-loop mathematical substitution would be inadequate. The plan requires a full source clone and reachable-type enumeration before candidate acceptance. This review does not assert all eight generic branches are reachable for exact native LU storage. No zero product may be skipped, including on nonfinite inputs.

4. **Failures and partial writes.** Three-argument factorization solve copies first (`factorization.jl:156-165`). Forward solve then applies pivots before L/U; transpose applies inverse pivots after U-transpose/L-transpose (`lu.jl:504-520,559-571`). Singular checks in generic triangular code can follow destination writes. The plan correctly keeps unsupported dimensions on the original whole route and requires exact exception type/message and destination post-unwind tokens for eligible malformed factors. No prevalidation pivot scan, catch/recompute, or leaf fallback is proposed. Resource-exhaustion timing is explicitly outside equivalence, an appropriate limitation for allocation removal.

5. **Small/unsupported calls and dependency/version scope.** Eligibility uses exact types and constant-time dimensions, n16 and rounding state. Fallback must allocate no MA scratch. Task2 includes empty/small, mismatched-rounding, Float64 and Rational controls. Production currently has no direct MA dependency; the plan explicitly requires one, initially pins MA1.8.1, and requires a clean load test and a supported Julia implementation boundary. Broad Julia compat is not proof of private-helper compatibility. Import/compilation/dependency costs remain separately visible. All runtime admission source mappings, including the reached normalization helpers in `adjtrans.jl`, still have to be frozen in MA-R/MA-S.

## Computational work and memory

No unnecessary added production work or retained memory was found in the proposed design; no production code changed in this step. The affected frequency is each eligible complete FTRAN/BTRAN backend invocation, including calls made during ordinary iterations or recovery/certification. Factorization, refactorization and eta-chain arithmetic are unchanged. The gate adds O(1) metadata work and one fresh product constructor. Existing copy/pivot work is O(n); existing `istriu` inspection can be O(n²), and must not be duplicated or hoisted. Both triangular solves still visit n(n-1) products in ordinary square paths, even for zero-heavy storage. Subtraction/division and wrapper-derived work remain; no extra solves, matrix conversions, full-vector scans, ownership scans or output copies are proposed. Scratch retains O(p) bits only during the call and introduces no update-chain-length retention. Source opportunities n(n-1)-1 (239/991/4031 at n16/32/64) are constructor opportunities, not measured allocation events or released native bytes.

The fixed cost schedule independently recounts to 36 targets plus 16 controls and `52 × 3 × (3+7) × 2 × 4 = 12,480` complete backend calls. There are 21 measured pairs per case across three serial processes. Routing and scratch construction remain inside each whole-call window; factor construction/reset and checks remain outside, equally on both sides. Correctness and RED calls are additional and must be enumerated before launch. All cases must pass prospective allocation/time criteria; GC/outliers remain and no post-result threshold tuning is permitted. Three processes and explicit noise budgets improve the design but do not establish significance. Actual savings, small-path overhead, cold import impact, precision scaling and nonfinite equivalence are unmeasured. The later public afiro/sc50a and PFI update-chain validations are distinct gates; no large-HH/full-suite benefit is claimed. Documentation requires no numerical benchmark now.
