## Work, memory and interpretation limits

No production change introduces unnecessary computational work or retained memory. This experiment deliberately adds bounded diagnostic work: each input token is an O(nnz+m+n) traversal/conversion outside measured solve windows, each endpoint token an O(n) traversal, and fixed observer dictionaries/timing calls only in diagnosed solves. The plain loop currently constructs an unused diagnostic object outside its timing window; this small avoidable harness allocation is not a production cost and does not invalidate this bounded characterization, but contributes to surrounding GC state. Existing diagnostic event retention is capped at 64 entries. Sampling retains up to 64 (Float64) or eight (other precisions) solution objects, hence O(batch*n) endpoint storage, and the profiler reserves two million instruction-pointer slots (16 MB before exported copies/frame dictionaries/string serialization). This retention and serialization are bounded by the fixed cases and resource guard. Full pin hashing is repeated outside numerical solve windows and is justified by artifact integrity.

Default verbose logging remains enabled by the chosen default options. Therefore reported full-solve time/allocations and sampled stacks include logging/formatting and redirected-file I/O; native/runtime/GC and logging costs must remain visible and must not be described as pure simplex-kernel costs. Outside-window token conversions, diagnostic construction, differing allocation histories and retained baseline/warm results can perturb GC timing. Preserve all three pairs and GC outliers and do not infer a speedup from this characterization. Sampling batch metrics include vector construction and profiler start/stop overhead and are not substitutes for the ordinary windows. Three repeats and potentially few 1-ms samples give limited precision. Ancestry category priority is a documented heuristic; inclusive kernel timers and function counts overlap and must not be summed. The small sparse fixtures plus chain do not cover large/dense LPs, HH/Markowitz, other precisions or general update-chain scaling. These limits are compatible with admission for this short experiment and should appear in the eventual result/recommendation.

No admission-blocking findings. Proceed only with these exact reviewed artifacts; numerical success and actionable attribution remain unproven until the guarded run and independent result review.
