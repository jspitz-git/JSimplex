# Devex quality reset — implementation and experiment plan

Goal: Test whether an inexpensive selected-row Devex quality indicator and deferred framework reset reduce iterations and total solve/dual-loop time on runtime.mps, without changing numerical safeguards.
Architecture: Isolated source snapshot and process-local function overrides. Production HH and FT, Float64/native160/fixed Devex/legacy/no presolve/1 Julia and BLAS thread/Inf time and maxInt iterations. Keep original reset at ordinary refactorization. No local-incidence or conveyor candidate.

Alternatives considered: a new basis solve/full DSE norm (wrong target and expensive); recomputing the whole Devex framework's weights (expensive); reusing the already computed reference sum for the selected row (chosen). User selected HH+FT first. Threshold9 and post-commit application are implementer choices for this isolated experiment, not production recommendations.

- [ ] Unit original-negative then candidate: exact threshold9, positive/finite operands, underestimated/overestimated, max1 clipping, reset count, changed-index authority, unsupported callbacks/aliasing, stage/retry/exception/refactor/phase invalidation, unchanged non-pricing state and safeguards, reference-sum oracle, two small full solves.
- [ ] Sequential smoke afiro/sc50a × HH/FT × off/passive/active: all OPTIMAL, original primal feasibility and actual certificate; passive/off exact events/guards/sampled-state/final. Full-runtime jobs start only after all smoke jobs succeed.
- [ ] Six complete runtime audits: off/passive exact endpoint and original event/guard/sample stream; independently recompute every observed reference sum. Active requires unchanged input/options/factory, original feasibility and actual original optimality certificate; report objective delta, iterations, refactors and guard counts. Zero hits explicitly means no demonstrated trajectory benefit.
- [ ] Twelve independent benchmark processes, two repeats with fully reversed manager/arm order: same afiro+100 input warmup outside measurement; whole JS.solve and whole dual optimize loop measured. No audit wrappers/copies/hash scans inside timed solve. Same O(1) factory observation and original certificate observer in all arms. Prototype metadata lookup remains in passive/active and is not subtracted.
- [ ] Verify all source/input pins, comparison/process reports, actual modes, true feasibility/certificate, sequencing and reverse order. Summarize each repeat, ratios of means, GC/compilation/allocations/bytes/RSS, observed proposals/resets/invalidations and runtime trajectories. Czech interpretation and final-verification; report timing uncertainty and changed trajectories, no kernel-speedup claim from fewer iterations.

Locks: own → legacy-pricing-check-reuse terminal+lock → all earlier suite locks. Recheck predecessor after all locks; release locks acquired so far on repair or nonterminal predecessor. All Julia child processes inherit every FD. Started markers exclude silent retries. Julia numerical validation is deferred behind the running measurement queue; preparation is not a claim of passed numerical tests.

Policy: request iff both weights finite positive and min/max <1/9. Record after existing sum in update_devex!. Consume only when the same live workspace advances exactly one successful ordinary pivot, with unchanged refactor/reset generation/phase, same Devex authority and nonaliased reset arrays. Apply after original _dual_after_iteration! returns nothing. Discard for stages, failed publication, exception, rebuild and phase/reset. Never repair invalid numeric state by filling weights. Existing reset then full _finite_workspace; return original numerical failure if it fails. No extra factorization/BTRAN/FTRAN/pricing scan on ordinary iterations. A reset may change future work and conditioning; outcomes must be measured.
