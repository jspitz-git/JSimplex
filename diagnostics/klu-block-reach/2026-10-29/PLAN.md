Assert nonempty ordered blocks, row/column permutations, block-diagonal L/U, strictly block-upper F, finite coefficients/scales/nonzero U diagonals, <=5M stored L/U/F. Construct block CSR with one edge per stored F slot, flag exact zero entries separately. Direction for FTRAN is column block -> earlier row block. BTRAN uses reverse edges and its seed from original basis-column block (`Q`), not original matrix-row block (`P`). FTRAN seeds from the actual entering column's nonzero original rows through P. Keep duplicate F edges, so reach-discovery visits include their real cost; no optimistic O(1) block-edge compression assumption. Test all3-vertex upper DAGs/all seed subsets versus independent Floyd closure in BOTH directions; explicit zeros, duplicates and three update-classification cases are covered with ordinary Test.

For every RHS record seed/reached blocks, active rows, active stored L+U, and coefficient-visit weights. L+U-n counts off-diagonal factor coefficients plus U diagonal divisions; implicit unit L diagonal is excluded. Block-only solve model visits L/U in reached blocks plus all F column slots of reached blocks, as in native column-based solve. Additional edge-aware BTRAN model counts only dependency-source-reached F slots and requires a reverse index; it is explicitly separate, not a free saving. Neither count equals measured machine instructions/flops or a proved skip implementation. Dense gather/scatter/clearing O(n), reach/index maintenance, callback/exception/finite/residual behavior and signed zeros remain obligations.

Classify the next exact column difference in CURRENT old block coordinates: changes in diagonal block, above-block couplings, below-block entries, and potential changed row-sum scaling rows. No below-block change preserves the old upper partition (allowing an individual block to split internally); coupling-only changes leave diagonal blocks unchanged ONLY with fixed permutations/scales. Native row-sum recomputation can change factors outside that block, so this is not admission for reusing numeric factors. Report affected block dimension. Canonical minimum original column-slot token per block permits membership comparisons across consecutive partitions without mistaking block-number reordering for a structural change. This detects column-partition equality, not row ownership/scaling equality. The changed-token count is the number of columns whose canonical group label changed, not the number of all columns participating in a changed block.
