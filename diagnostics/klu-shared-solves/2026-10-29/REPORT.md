## Why recovery weights are the first additional consumer

src/simplex_recovery.jl:92–130 builds a private recovery trial, invokes `_basis_factorization(B, options)`, performs `_after_basis_refactor!`, recompute and reliability checks, then calls `_rebuild_recovery_weights!`. A second production caller, `_transfer_precision` in src/simplex_precision.jl:184–218, also constructs a fresh factor and recomputes before calling the same helper. Both must be accounted for; the proposed KLU experiment is Float64-only and does not optimize the other precision paths. The latter returns early unless dual steepest_edge is active; otherwise it allocates local dense rhs/direction, loops over every basic row, checks stop, fills a unit rhs, calls transpose_solve!, then refine_basis_solve!, computes dot(direction,direction), checks finite positive weight, and applies the original floor. This is conditional recovery work, not one mandatory weight rebuild every iteration.

Ordinary PFI's new updates vector is empty, ordinary FT/SS/BG start with identity upper and no row-update history. In the uninterrupted internal fresh-factor path there is no accepted pivot between construction and weight rebuild; recomputation is a solve, not a column replacement. Thus these weight calls reach the **full base** with a unit support. This is a source argument under private ownership/no external mutation; arbitrary stop/logger/observer mutation cannot certify a permanently fresh factor. A candidate must bind factor identity/generation and reject/fallback after mutation/refactor/unknown callbacks, and preserve all stop/exception behavior. DirectLowerBackend and non-full-base prototype exporters are excluded. Current production does not have this KLU backend; no factory was modified.

This narrows a previous caveat: general BTRAN may be dense at the base boundary, but the fresh-factor weight consumer has a justified unit case. The source loop enumerates all n basic positions, unlike the old selected next leaving row. Its cost therefore must use an all-unit distribution.

## Complete work and memory ledger

Let n be basis dimension, N the number of original working columns (states have lengthN+n), zB current basis NNZ, zF coupling NNZ and k reached blocks. Shared preparation already paid by FTRAN includes owned L/U/F/P/Q/R/Rs, block maps/weights and work. BTRAN needs inverseQ plus a reverse F numeric index; one conservative layout is rowptr(n+1), F-entry positions(zF), source columns(zF), inverseQ(n), total8*(2n+1+2zF) bytes. Runtime upper payload is1.40–1.50MiB beyond existing exports, excluding headers/capacity and any new scratch/heap. Reuse existing solve scratch sequentially where safe; no second numeric-value export, no L/U transpose copies and no per-unit reach table. Actual context size/native duplication must be measured; existing graph candidate extra5.53–6.81MiB is not erased by adding a consumer.

Per independent unit BTRAN: original dense RHS fill O(n), Q gather/seed, active U'/L' solves, reverse F propagation with priority/topological work O(k log nb), P scatter/postscale O(n), output clears required by representation. No extra full-vector support search for a privately produced unit. Native/unknown/dense/failure route remains available; sunk candidate work plus full fallback remains charged.

Per recovery-weight row, the surrounding code still performs: stop checks; refine_basis_solve! with alias checks and `_basis_matrix!` validation/assembly (including basic-mask reset and the N+n state-consistency scan); owned RHS copy; complete finite/residual/scale/error computations on current B; bounded corrections/rechecks if needed; dot(direction,direction) over n entries; finite/positive/floor check and weight write. `_basis_matrix!` is borrowed assembly on every call, not just a pointer lookup (src/simplex.jl:266). Typical quality path has O(zB+n) work and can escalate to compensated/wide work; callbacks/corrections remain unchanged. On the normal reliable path, a completed full rebuild therefore retains surrounding traversals scaling as **Theta(n*(N+n+zB))**, even if base BTRAN coefficient visits shrink; corrections/fallbacks may add more. No graph of exported factors can replace a residual against actual B or original-model certification. No repeated invariant check or safeguard is removed in this proposal.

Adding n potential solves improves amortization of preparation only when that conditional rebuild actually occurs; we have no current whole-LP count/frequency. Fixed-base graph use after ordinary refactors is separate from dynamic SCC maintenance. Do not promise recovery speedup or whole-solver speed from this structural work ratio.

## Recommended next experiment

Use one isolated shared full-KLU context and a unit-only **weight consumer**, leaving aged generic BTRAN native. Qualify transposed arithmetic, original-B residual and original per-row refinement/weight checks on a small deterministic stratified sample from each captured base; report sample coverage and all-unit structural totals separately. Compare full exported Julia, local indexed Julia, native single-RHS and native multi-RHS where stop/order semantics permit. Include complete sample-weight handling and preparation once per context, not only solves. Independently compare a direct transposed solve on the same B; numerical policy and tolerances unchanged. Signed-zero differences remain a prospective ownership/observability obligation; a local scalar-weight consumer may have narrower exposure than public FTRAN, but this is not yet a proof.

The same bounded future process should separate the four preparation stages using explicit included observation overhead, so source attribution precedes any generator/sort rewrite. Decision gates: repeated-call benefit against native; inclusive preparation+sample/rebuild accounting, extra index memory; no numerical/callback/stop/exception regression; dense/unknown fallback; exact private cache invalidation and no value copies per unit. A sample benchmark cannot certify a full n-row rebuild or current-LP speedup. Whole rebuild timing is a later step only if the bounded sample and preserved quality costs justify it.

This is an investigated direction and a prospective experiment contract, not a new executable BTRAN candidate, loading/launch admission, production integration or authority to rerun frozen artifacts.
