## Important issue before an implementation plan

1. **Imported stored zeros conflict with literal incidence-list rotation and the unchanged original SS representation.** `src/triangular_factorization.jl:1039` obtains the moved-row coefficient, but deletes the packed entry only when it is nonzero. It then decrements packed row ids in `(position,last]`. An explicit zero at `position` therefore remains there; if the same column also stores `position+1`, decrementing that entry creates duplicate packed row ids. A literal rotation of reverse row lists instead moves every stored occurrence of the old row to `last`. These representations disagree. The export checker permits finite explicit zeros (`factor-export.jl:26` onward), and `_direct_packed_upper` copies them, so the design cannot assume this input is impossible. The proposed one-coordinate/one-incidence invariant and freshly rebuilt incidence oracle are not sufficient to preserve the existing scalar behavior in this case.

   Resolve conservatively in the design: during the already-required initial index/diagonal scan, mark a factor ineligible for the local route when imported U contains any stored explicit zero. Keep its chain on the original SS path until the next refactorization can produce eligible U. Preserve original storage, exceptions, and arithmetic; do not normalize away zeros or repair the original update as part of this project. Differential tests should explicitly exercise this refusal, including copied factors. The eligible candidate's packer/setters already omit or delete computed exact zeros. This adds no scan and avoids trying to maintain a unique-coordinate graph over an original path that can cease to be canonical.

## Other requested boundaries

- **Sparse skips:** current U incidence, dynamically enqueued fill, minimum pivot order, touched-tail stores, and trailing coupling columns cover the important structural hazards. The finite/nonzero diagonal proof must be maintained or the original scalar path used; the design states that requirement. Old BTF labels do not authorize skips. No further important gap found here.
- **Fallback safety:** the newly specified phase reservation and explicit remainder state address the original mid-mutation replay hazard. A fallback must carry current scratch, next pivot, completed history, and touched-tail state, and disable metadata until refactorization. No fallback halfway through a swap is allowed. This is a substantive implementation/test obligation, not a reason to ask the user another design question.
- **KLU versus direct export:** these are correctly separated. The saved guide gives `L*U+F = R\A(p,q)`; the existing direct adapter requires a multiplicative L/U identity. Flattening F would require the additional transformed coupling upper and can add fill. Ordinary native KLU solves are a valid independently rejectable first gate. The saved KLU.jl source copies input values in its CSC constructor and allocates on factor-property extraction; the design correctly calls for checking ownership from pinned source and avoids extraction in solve windows.
- **Numerical pivot policy:** the design correctly retains the UMFPACK control vector and does not infer an equivalent KLU tolerance. KLU's default diagonal preference is 0.001; UMFPACK has separate ordinary and symmetric diagonal pivot controls. In particular, the repository's `threshold_one` path sets `UMFPACK_PIVOT_TOLERANCE=1` and `IRSTEP=0`, not the symmetric diagonal tolerance. A later policy mapping must inspect the actual strategy/control settings and cannot infer a global multiplier bound merely from the option name. The current backend-policy comparison wording is adequate; no additional design blocker.
- **Work and memory:** no production change or unnecessary executed cost was introduced by this design. Static review found no further unacknowledged mandatory full scan, extra numeric LU, duplicate KLU matching pass, or per-solve graph pass. Reverse incidence maintenance, sorted-list shifts, support copies, O(d) physical rotations, fallback sunk work, capacity retention, candidate publication peaks, and native payload are explicitly charged. Their profitability remains unproved; whole-cycle paired measurements are required later. No benchmark is warranted for this source-only review.
